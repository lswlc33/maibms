## 7.1 命令帧结构

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：实测 `51 + 命令号小端`（蜂鸣器 30 → `7E A1 51 1E 00 00 E9 23 AA 55`）。

### 无参数命令（多数情况）

```
7E A1 51 <命令号2B 小端> 00 CRC AA 55
```

- 功能码 `51`
- 寄存器 = **命令号**（不是参数地址）
- 长度 = `00`（无数据）

示例：打开充电 MOS（命令号 6）

```
7E A1 51 06 00 00 69 24 AA 55
        └─┬─┘ └┬┘
   命令号 0x0006
          长度 0
```

### 带参数命令

少数命令需要携带数据（如芯片切换、时间校准），此时长度非 0，数据区按命令定义填写。

## 7.2 控制命令全表

> 🟠 **实测部分验证**（2026-09-29 同上）：仅实测过命令号 30（蜂鸣器）；其余命令号待验证。

下表命令号来自旧版 App 控制页面的实际下发（`pages/BmsControl`）。
**新版沿用同一套命令号**，只是部分操作改用了其他功能码（见 [7.6 节](#76-新版差异)）。

### 开关控制

| 命令号 | 功能 | 报文 |
|---|---|---|
| 1 | 放电开关 — 关闭 | `7E A1 51 01 00 00 XX XX AA 55` |
| 3 | 放电开关 — 打开 | `7E A1 51 03 00 00 XX XX AA 55` |
| 4 | 充电开关 — 关闭 | `7E A1 51 04 00 00 XX XX AA 55` |
| 6 | 充电开关 — 打开 ★ | `7E A1 51 06 00 00 69 24 AA 55` |
| 52 | 强制开启充电 | |

> 「打开」= 允许 MOS 导通；「关闭」= 主动断开 MOS。
> 关闭充电 MOS 后，即使接入充电器也不会充电（常用于运输模式、故障隔离）。

### 均衡控制

| 命令号 | 功能 |
|---|---|
| 13 | 打开均衡 |
| 14 | 关闭均衡 |

### 系统控制

| 命令号 | 功能 | 说明 |
|---|---|---|
| 7 | **保存应用参数** ★ | 参数写入 flash，见 [第 6.6 节](06-参数读写.md#66-保存与生效) |
| 8 | 电流归零 | 电流传感器零点校准（**需在无电流状态下执行**） |
| 9 | 重启系统 | 旧版；新版改用功能码 `57` |
| 11 | 关闭系统 | 断电关机 |
| 12 | 恢复出厂设置 | 谨慎使用 |
| 15 | 清除系统日志 | |
| 16 | 蓝牙初始化 | 蓝牙模块复位 |
| 28 | 蓝牙关闭 | 关闭后无法再通过蓝牙连接（**慎用**） |
| 29 | 蓝牙打开 | |
| 30 | 蜂鸣器打开 | |
| 31 | 蜂鸣器关闭 | |
| 42 | 恢复厂家设置 | 比出厂恢复更彻底，**慎用** |
| 44 | 保存用户数据 | |
| 45 | 用户参数 | 读取/应用用户参数组 |

### 电池类型预设

| 命令号 | 功能 | 说明 |
|---|---|---|
| 38 | 钛锂参数 | 一键套用钛酸锂阈值组合 |
| 39 | 三元参数 | 一键套用三元锂阈值组合 |
| 40 | 铁锂参数 | 一键套用磷酸铁锂阈值组合 |
| 53 | 钠电参数 | 一键套用钠离子电池阈值组合 |

> 预设本质上是把一整套保护阈值（单体过压/欠压、总压、温度等）批量写入参数区。
> 套用后仍需 `51/07` 保存才生效。

### 数据清零

| 命令号 | 功能 |
|---|---|
| 32 | 清总放电容量 |
| 33 | 清总充电容量 |
| 34 | 清总放电时间 |
| 35 | 清总充电时间 |
| 36 | 清零运行时间 |
| 37 | 清零保护次数 |

> 新版参数表的写法：`5107` = 功能码 `51` + 命令号 `07`（保存应用参数）；
> `5126`~`5128` = 命令号 `26`~`28`（= 38~40，钛锂/三元/铁锂）；`5135` = 命令号 53（钠电）。
> 详见 [附录 A.10](附录A-参数寄存器表.md#a10-新版命令码写法)。

## 7.3 应答与结果码

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：实测 `0x61` 应答 `reg` = 命令号、数据区 2 字节 u16 结果码（该机权限不足返回 3）。

### 应答帧

```
7E A1 61 <命令号2B> <长度> <结果码1B> ... CRC AA 55
```

寄存器字段回显命令号，数据区首字节为结果码。

### 结果码

`0x61` 应答的数据区前 2 字节是结果码（u16 小端；取值都很小，只读第 1 字节也可）：

| 码 | 含义（新版文案） | 含义（旧版文案） |
|---|---|---|
| 0 | 无（不提示） | 无（不提示） |
| 1 | **成功** | 操作成功 |
| 2 | 失败 | 失败 |
| 3 | 权限不足 | 权限不够，请校验权限 |
| 4 | 地址超限 | 地址超范围 |
| 5 | 电池类型错误 | 电池类型错误 |
| 6 | 电池信息错误 | 电流信息错误 |
| 7 | 固件不匹配 | 固件不匹配 |

两版源码完全一致（旧版 `app.js` 的 `h()` 与新版 `handleSetParamsResult` 的 `"61"` 分支），
仅第 6 项文案有出入。

> **⚠ 不要与其他码表混用**：`0x61` 用的是上面这张表；
> 而「小于允许最小值 / 大于允许最大值」是**写参数**的码表
> （见 [第 6.5 节](06-参数读写.md#65-结果码与失败提示)），出现在 `0xFF` 附加段里，不在 `0x61` 中。

新版对 `0x61` 的实现还有一个细节：它从**原始十六进制串的第 12~14 个字符**
（即数据区首字节）取码，再由上表转成文案并弹出提示。

## 7.4 典型操作流程

### 例 1：打开充电 MOS

```
① 确认权限（读实时数据，看偏移 0 的权限值 ≥ 3）
② 发命令：7E A1 51 06 00 00 69 24 AA 55
③ 收应答：7E A1 61 06 00 01 ... AA 55     → 结果码 1 = 成功
④ 轮询实时数据，检查"充电 MOS 状态"（尾部相对偏移 13）= 1
```

### 例 2：修改单体过压保护并保存

```
① 权限校验：7E A1 23 4A 01 08 3132333435363738 DB 50 AA 55
② 写参数  ：7E A1 22 04 00 02 42 0E 4C 2C AA 55     （3.650 V）
③ 收 42 应答，结果码 1
④ 保存    ：7E A1 51 07 00 00 38 E4 AA 55
⑤ 收 61 应答，结果码 1
⑥ 回读校验：7E A1 02 04 00 02 XX XX AA 55
```

### 例 3：套用铁锂预设

```
① 7E A1 51 28 00 00 XX XX AA 55     （命令号 40 = 0x28）
② 等 61 应答成功
③ 7E A1 51 07 00 00 38 E4 AA 55     （保存）
④ 可选：分块回读参数区确认阈值已变
```

## 7.5 从机 / 并联数据（寄存器 0x3800）

当 BMS 处于多从机（并联/分级）形态时，同一功能码 `51` 用一个特殊寄存器返回**从机基础数据**。
App 内部代号 `_0X3800`，即寄存器字节为 `38 00`（小端存放，值 = 0x0038 = 56）。

### 数据区布局

| 偏移 | 长度 | 字段 | 解码 |
|---|---|---|---|
| 0 | 1 | 当前从机地址 | 原值 |
| 1 | 1 | 总从机数 | 原值 |
| 2 | 1 | 单体电压有效数 | 原值 |
| 3 | 1 | 温度有效数 | 原值 |
| 4 | 4 | 均衡标志位 | u32 位图（见下） |
| 8 | 2×24 | 单体电压 1 ~ 24 | u16 ÷1000，单位 V；描述符标注 `andData = 3`（低 2 位为标志位），**但当前实现未做屏蔽** |
| 56 | 2×4 | 电芯温度 1 ~ 4 | s16，℃ |
| 64 | 2 | 均衡温度 | s16，℃ |
| 66 | 1 | 单体最高所在位置 | 原值 |
| 67 | 1 | 单体最低所在位置 | 原值 |
| 68 | 2 | 单体累加总压和 | u16 ÷100，V |
| 70 | 2 | 单体测量总压和 | u16 ÷100，V |

注意两点：

- 描述符里写了 `andData = 3`（即应为低 2 位标志 + 高位电压），与 `0x11` 帧的 3 位标志不同；
- 但 App 的 `analysisSlaveInfo` 实际调用的是 `getNumberVal(bytes, type, range)`，
  **并没有应用 `andData`**，因此它读到的就是原始 u16 ÷1000。
  自己实现时建议按 `v & 0x3FFF` 之类的掩码先屏蔽标志位，或与实机数据比对后决定。

### 均衡标志位（u32，偏移 4）

```
bit0 ~ bit19   →  第 1 ~ 20 串是否在均衡
高字节 bit5    →  存在最高单体值
高字节 bit6    →  存在最低单体值
高字节 bit7    →  采集从机已连接
```

参考实现：

```python
flag = u32(data, 4)
balance = [(flag >> i) & 1 for i in range(20)]     # 第 1~20 串
high_byte = (flag >> 16) & 0xFF
has_max  = bool((high_byte >> 5) & 1)
has_min  = bool((high_byte >> 6) & 1)
connected = bool((high_byte >> 7) & 1)
```

## 7.6 新版差异

| 操作 | 旧版 | 新版 |
|---|---|---|
| 重启系统 | 功能码 `51` + 命令号 `9` | 功能码 `57`，命令名 `restartSystem`，应答 `67` |
| 参数保存（BMS） | `51/07` | 同上，命令名 `saveAppParamters` |
| 参数保存（DTU） | — | `53` + `saveAppParam`，应答 `63` |
| 蓝牙参数保存 | — | `57` + `saveParam`，应答 `67` |
| 屏幕参数保存 | — | `56` + `saveParam` / `saveApplication`，应答 `66` |
| 芯片切换 | — | `59` + `changeChipsN`，应答 `69` |
| 控制命令 | 硬编码命令号 | 由服务端协议模板给出，命令名如 `customControl1` |

新版把「保存」按目标设备拆成了四个功能码，这是因为它同时管理 BMS、DTU、蓝牙模块、屏幕四类设备：

```
51 → 61   保存到 BMS
53 → 63   保存到 DTU
56 → 66   保存到屏幕 / 应用配置
57 → 67   保存到蓝牙模块
```

> 对接 BMS 时，最常用的仍是 `51/07`（保存应用参数）。
