## 5.1 请求与应答

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：请求帧 `7E A1 01 00 00 F5 58 62 AA 55` 实测可用；该机应答数据区 **168 字节**（长度随 N/M 变，非固定 186/245）。

### 请求（短帧，10 字节）

```
7E A1 01 00 00 F5 58 62 AA 55
         └─┬─┘ └┬┘
  功能码 01   │  └── 长度 = 245（希望设备返回最多 245 字节）
  寄存器 = 0  └───── 起始地址固定 0
```

| 变体 | 报文 | 说明 |
|---|---|---|
| 新版（推荐） | `7E A1 01 00 00 F5 58 62 AA 55` | 请求 245 字节，拿到全部字段（含扩展段） |
| 旧版 | `7E A1 01 00 00 BE 18 55 AA 55` | 请求 190 字节 |
| 更早年 | `7E A1 01 00 00 9C 98 4C AA 55` | 请求 156 字节 |

请求长度只是「上限」，设备返回多少由固件与电池配置决定。

### 应答（长帧）

```
7E A1 11 00 00 <N> <数据区 N 字节> <CRC_L CRC_H> AA 55
```

**应答的功能码恒为 `0x11`，寄存器字段为 `00 00`**（请求的是什么就回什么，实时数据固定用 0）。
总帧长 = `10 + N`。

> App 判定一帧是不是实时数据，用的就是前缀 `7ea11100` / `7ec11100`（功能码 + 寄存器低字节）。

## 5.2 数据区总体布局

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：20S/4T 机型实测 T0 = 28 + 2N + 2M = 76，字段逐项自洽。

数据区由三部分组成，长度随电池串数 N、温度数 M 变化：

```
┌────────────┬─────────────────┬──────────────┬─────────────────────────────────┐
│ 固定头部    │ 单体电压 1..N    │ 温度 1..M     │ 尾部固定区（紧接数组之后）        │
│ 28 字节     │ 2N 字节          │ 2M 字节       │  核心段 78B  +  扩展段 24B(可选)  │
└────────────┴─────────────────┴──────────────┴─────────────────────────────────┘
 偏移 0        28                28+2N          28+2N+2M (T0)   T0+78        T0+102
                                                              └─ 扩展段起点   └─ 数据区末尾

                    定义 T0 = 28 + 2N + 2M   （尾部起点）
```

| 段 | 长度 | 是否必需 | 说明 |
|---|---|---|---|
| 固定头部 | 28 | 必需 | 权限、状态、标志位、数组长度 |
| 单体电压数组 | 2N | 必需（N = 数据区偏移 3 的字节） | |
| 温度数组 | 2M | 必需（M = 数据区偏移 2 的字节） | |
| **核心段**（尾部前 78 字节） | 78 | 必需 | 到「累计充电时间」为止 |
| **扩展段**（尾部后 24 字节） | 24 | 可选，旧固件不返回 | 本次充电时长、充电器信息等 |

**总长度**：

```
核心版 = 106 + 2N + 2M        （固定头部 + 数组 + 核心段）
完整版 = 130 + 2N + 2M        （核心版 + 扩展段）
```

> 新版 App 的判断条件是 `数据长度 > 106 + 2N + 2M`，成立才继续解析扩展段。
> 因此解码器应当**按长度逐段保护**：数据不够就跳过，不要越界读。

例：16 串 4 温度 → `T0 = 28 + 32 + 8 = 68`，核心版 `106 + 40 = 146`，完整版 `130 + 40 = 170` 字节。

> ⚠ **别忘了解析层的 192 字节上限**：完整版长度必须 ≤ 192，即 `N + M ≤ 31`。
> 24S + 4T（186 字节）刚好在限内，32S 以上就要留意了 —— 详见
> [第 3.2 节](03-帧格式与校验.md#32-短帧与长帧)的推论。

## 5.3 固定头部（偏移 0 ~ 27）

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：权限/状态/M/N/保护位域/告警位域 实测偏移正确（告警 bit0 实测置位）。

| 偏移 | 长度 | 字段 | 解码 | 含义 |
|---|---|---|---|---|
| 0 | 1 | 当前权限 | 原值 | 0 = 无权限；≥1 可读；≥3 可写；5 = 可升级采集芯片；9 = 最高 |
| 1 | 1 | 电池状态 | 查表 | 1 静止 / 2 充电 / 3 待机 / 4 放电 / 5 异常 |
| 2 | 1 | **温度数量 M** | 原值 | 决定温度数组长度 |
| 3 | 1 | **单体数量 N** | 原值 | 决定电压数组长度 |
| 4 | 8 | 保护标志位 | u64 位域 | 见 [第 13.1 节](13-位域与枚举字典.md#131-保护标志位64-位) |
| 12 | 8 | 告警标志位 | u64 位域 | 见 [第 13.2 节](13-位域与枚举字典.md#132-告警标志位64-位) |
| 20 | 8 | 推送标志位 | u64 位域 | 主动推送事件标志（App 仅透传，语义未公开） |

> **两个数字要记住**：`M = 数据[2]`、`N = 数据[3]`。
> 解码任何一条 `0x11` 报文，第一步都是读出这两个值来算出后续所有偏移。

### 64 位标志的字节序

8 字节按小端 u64 读取：

```python
protect = int.from_bytes(data[4:12], 'little')
# 位 i 对应"保护位表"的第 i 项
active = [name for i, name in enumerate(protect_names) if protect >> i & 1]
```

等价于：**前 4 字节是低 32 位（表 0~31 项），后 4 字节是高 32 位（表 32~63 项）**。
旧版源码里把它们分别存为 `ProtectMack_Bit1`（前 4 字节）和 `ProtectMack_Bit2`（后 4 字节），
拼接方式是 `ProtectMackString[k]`（k<32 取 Bit1 的第 k 位）与 `ProtectMackString[32+k]`（Bit2 的第 k 位）。

## 5.4 变长数组：单体电压与温度

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：实测 `& 0x1FFF` 后 ÷1000 得单体电压；温度为 s16；索引 1 起。

### 单体电压（偏移 28 起，共 N 项，每项 2 字节）

```
原始 16 位 = [bit15 bit14 bit13 | bit12 ... bit0]
             └── 状态标志 3 位 ──┘ └── 电压值 13 位 ──┘

电压 = (u16 & 0x1FFF) ÷ 1000   （单位 V，范围 0 ~ 8.191 V）
```

三种状态的区分：

| 位 | 含义 |
|---|---|
| bit13 | 状态标志 A |
| bit14 | 状态标志 B |
| bit15 | 状态标志 C |

新版把这 3 位解析成数组 `bsErrSt`（任一非 0 就上报）；**旧版直接除以 1000，不屏蔽高位**，
因此遇到带标志位的固件会显示异常大的电压（如 8.192 V）。

> **⚠ 兼容性要点**：如果你照抄旧版逻辑，务必改成 `(v & 0x1FFF) / 1000`。
> 建议始终屏蔽高 3 位，并在 3 位非 0 时记录异常。

### 温度（紧跟电压数组，共 M 项，每项 2 字节）

```
温度 = s16（有符号 16 位小端）  单位 ℃
```

直接支持负温度（如 `D8 FF` = 0xFFD8 = **-40 ℃**）。
温度传感器未接入时通常返回 -40 或固定值。

由此得到：

```
温度数组起始偏移 = 28 + 2N
尾部起点 T0      = 28 + 2N + 2M
```

## 5.6 扩展段（相对偏移 78 ~ 101）

> 🟠 **实测部分验证**（2026-09-29 同上）：实测该机扩展段只有 **14 字节**（数据区 168 = 76 + 78 + 14），字段含义未逐项验证；解析请按长度判断。

|---|---|---|---|---|
| 78 | 4 | 本次充电时长 | u32 | 秒 |
| 82 | 4 | 上次充电间隔 | u32 | 秒 |
| 86 | 2 | 充电剩余时间 | u16 | 分钟 |
| 88 | 2 | 放电剩余时间 | u16 | 分钟 |
| 90 | 2 | 高速电流 | s16 ÷10 | A |
| 92 | 2 | 使用有效期 | u16 | 小时（授权/许可相关） |
| 94 | 2 | 采集故障 | u16 | 采集芯片上报的故障标志 |
| 96 | 2 | 充电器输出电压 | u16 ÷10 | V |
| 98 | 2 | 充电器输出电流 | u16 ÷10 | A |
| 100 | 2 | 充电器状态 | 位域 | bit15 = 已接入；低 15 位 = 状态码 |

> 偏移 78 ~ 85 的两项在不同固件里也可能被解析为「充电开始时间 / 充电时长」，
> 语义属于统计量的延续，实测时以数值合理性判断。

> **字段类型与倍率以解析器描述符为准**（`bms_0x11_1.0.0.js` 的 50 个描述符）：
> 本表的每一行都已与该描述符表逐项核对（长度、类型、倍率）。
> 例如「高速电流」是 **short ÷10**（有符号、单位 A），而不是无符号原值。

### 充电器状态位

```python
chargerState = u16(相对偏移 100)
接入   = bool(chargerState & 0x8000)          # bit15
状态码 = chargerState & 0x7FFF
```

App 的实现是先把该值转成 16 位二进制字符串，取第 1 位作为「接入」标志，其余 15 位作为状态码。

## 5.7 主动均衡结构体

尾部相对偏移 36 的 4 字节（`均衡标志位`）有**两种截然不同的含义**，
取决于设备是不是主动均衡机型：

### 普通机型：位图

```
u32 位图，bit i = 1 → 第 (i+1) 串正在均衡
```

### 主动均衡机型：结构体

判断依据：`bmsType`（偏移 T0+15）与扩展帧 `0xFE` 上报的机型
（见 [第 11 章](11-采集芯片与扩展帧.md)）。为主动均衡机型时，同样的 4 字节按结构体解读：

```
字节 3        字节 2        字节 1          字节 0
┌──────────┬───────────┬─────────────┬────────────┐
│ 均衡序号  │ 线阻÷100  │ 均衡电流(s8) │ 故障码     │
└──────────┴───────────┴─────────────┴────────────┘
  [31:24]     [23:16]      [15:8]         [7:0]
```

| 字段 | 提取 | 解码 |
|---|---|---|
| 均衡序号 | `(v >> 24) & 0xFF` | 正在均衡的串号 |
| 线阻 | `(v >> 16) & 0xFF` | ÷100，单位 mΩ |
| 均衡电流 | `(v >> 8) & 0xFF`，按 s8 解读 | bmsType 为 `2` 或 `33` 时 ÷10，其余 ÷100，单位 A |
| 故障码 | `v & 0xFF` | 0 = 正常 |

**有符号 8 位转换**：`v > 127 → v - 256`。

参考实现：

```python
def parse_active_bal(v: int, bms_type: int):
    cur_raw = (v >> 8) & 0xFF
    cur = cur_raw - 256 if cur_raw > 127 else cur_raw
    divisor = 10 if bms_type in (2, 33) else 100
    return {
        "balanceIdx":      (v >> 24) & 0xFF,
        "lineResistance":  ((v >> 16) & 0xFF) / 100.0,
        "balanceCurrent":  cur / divisor,
        "activeBalFault":  v & 0xFF,
    }
```

## 5.9 新旧解析差异与陷阱

| 差异点 | 旧版行为 | 新版行为 | 建议 |
|---|---|---|---|
| 单体电压高位 | 直接 `÷1000`，不屏蔽 bit13~15 | 先 `& 0x1FFF` | **按新版**，屏蔽高位 |
| 请求长度 | 190 字节 | 245 字节 | 245（字段更全） |
| 扩展段 | 无解析 | 有（本次充电时长、充电器信息等 24 字节） | 按长度判断，有则解析 |
| 均衡 4 字节 | 只当位图 | 主动均衡机型解析为结构体 | 按 `bmsType` / 机型判断 |
| 权限字段 | `SysOperationAuth` | `currentAuth` | 同一含义 |
| MOS 温度字段名 | `Temperature_MOS` | `batteryTemperatureNum`（命名有误） | 认偏移不认名字 |

### 五个常见错误

1. **忘记先用 N/M 算偏移**，直接按固定偏移读 → 串数不同的设备全部错位。
2. **单体电压不屏蔽高 3 位** → 出现 8.191 V 之类的怪值。
3. **温度当无符号读** → 负温度变成 65496 ℃ 之类。
4. **CRC 覆盖范围搞错**（长帧要覆盖数据区）→ 校验一直失败。
5. **把组合帧的第二段（`0xFE`）当成独立帧解析** → 找不到 `7E` 帧头，
   正确做法见 [第 3.3 节](03-帧格式与校验.md#33-组合帧)。
