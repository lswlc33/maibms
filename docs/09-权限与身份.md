## 9.1 五级权限体系

> 🟠 **实测部分验证**（2026-09-29 同上）：实测槽位 330（一级）与 338（二级）可校验通过、出厂默认 `12345678` 有效；346/354/362/374 未验证（三级槽实测不认默认密码）。

BMS 内置五级密码 + 一个「运行权限」计数器，两级概念要分清：

| 概念 | 含义 | 来源 |
|---|---|---|
| **密码** | 存储在参数区，每级 8 字节 ASCII | 参数地址 330 / 338 / 346 / 354 / 362 |
| **运行权限** | 当前会话已解锁到第几级 | 实时数据偏移 0（`当前权限`），或 `0x43` 应答 |

### 密码存储位置

旧版 App 的权限页（`pages/auth_check`）有**六个输入框**，写入时用功能码 `0x23`，
寄存器填「密码槽的起始地址」，长度填该槽的字节数：

| 等级 | 旧版地址 | **长度** | 新版命令码 | 输入格式 |
|---|---|---|---|---|
| 一级 | 330 | 8 字节 | `2301` | 8 位 ASCII，**出厂默认 `12345678`** |
| 二级 | 338 | 8 字节 | `2302` | 8 位 ASCII |
| 三级 | 346 | 8 字节 | `2303` | 8 位 ASCII |
| 四级 | 354 | 8 字节 | `2304` | 8 位 ASCII |
| 五级 | 362 | **12 字节** | `2305` | ≤12 位 ASCII（UI `maxlength="12"`） |
| **管理员** | **374** | **12 字节** | （新版无） | **点分十进制，12 段**（每段 ≤255） |

规律：前四级每级 **8 字节**，第五级与管理员级各 **12 字节**；
`362 + 12 = 374`，正好接续 —— 六个槽位共占 **330 ~ 385**（56 字节）。

补齐规则：八字节槽用 `0x00` 补到 8（`StrToLenUint8Array(pwd, 8)`），
十二字节槽补到 12。

> **管理员密码的输入格式特殊**：它不是直接输入字符串，而是要输入**点分十进制**的 12 段数字
> （如 `0.0.0.0.…`，源码 `pwdAdmin.split(".")`，要求 ≥12 段、每段 ≤255），
> 客户端再把每段转成一个字节写入。这与旧版把「芯片 ID」显示为点分十进制的做法同源
> （见 [第 9.4 节](#94-读取设备身份功能码-0x04)）。

> ⚠ **一处待实测的地址冲突**：新版参数表把**地址 374** 定义为「系统基准电压偏移（`bl16`，单位 mV）」，
> 而旧版把 374 当作管理员密码槽写入 12 字节。两种读法都有源码依据，推测与**固件代际**有关 ——
> 旧固件用「字节地址」标识密码槽（330…374），新固件的命令码改用「槽位号 1~5」（`2301~2305`）。
> 建议实测：向 374 写 12 字节后回读参数 374，看变化的是密码还是电压偏移。

### 运行权限的语义

| 权限值 | 能做什么 |
|---|---|
| 0 | 只能读实时数据 |
| ≥ 1 | 可读参数区、日志、身份 |
| ≥ 3 | **可写参数、执行控制命令** |
| 5 | 可升级采集芯片 |
| 9 | 最高权限（厂家级操作） |

> 旧版 App 的连接握手阶段会先读实时数据看权限值，
> 若 `< 1` 就自动发一级密码；写参数前若权限不足会跳转到权限校验页面。
> 新版有专门的权限弹窗（`permissionspop`）。

## 9.2 密码校验（功能码 0x23）

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：实测请求/应答格式、槽位地址、失败时权限不提升；注意判定要用「返回值 ≥ 所校验等级」。

### 请求（长帧）

```
7E A1 23 <槽位2B> <长度> <密码字节> CRC AA 55
```

- 功能码 `23`
- 寄存器 = 密码槽：`330` / `338` / `346` / `354` / **`362`** / **`374`**（旧版按字节地址书写）
- 长度 = 该槽的字节数：前四槽 `08`，第五槽与管理员槽 **`0C`**
- 数据 = 密码字节（ASCII；管理员槽为点分十进制逐段转成的字节）

示例：校验一级密码 `12345678`（8 字节槽）

```
地址 330 = 0x014A → 小端 4A 01
密码 ASCII：31 32 33 34 35 36 37 38
完整帧：7E A1 23 4A 01 08 31 32 33 34 35 36 37 38 DB 50 AA 55
```

### 应答（长帧）

```
7E A1 43 <地址2B> <长度> <权限值2B 小端> CRC AA 55
```

数据区前 2 字节即**校验通过后的运行权限等级**。
旧版实现直接取数据区偏移 6~7 组成权限值：

```javascript
SysOperationAuth = data[7] << 8 | data[6]
```

### 校验失败的表现

- 权限值不提升；
- 后续写参数会收到 `0x42` 结果码 `5`（密码不正确/权限不足）；
- 控制命令会收到 `0x61` 结果码 `5`。

## 9.3 权限应答与状态跟踪

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：实测 `0x43` 回的是当前运行权限；权限可跨 BLE 断连保持；写/控制需 ≥3 级。

一套完整交互中权限相关的信息流：

```
① 连接成功
② 读实时数据 → 偏移 0 得到"当前权限"基准值
③ 若需写操作 → 发 0x23 密码校验
④ 收 0x43 → 得到新的权限值，缓存到本地
⑤ 后续写参数/控制，设备侧按已解锁等级放行
⑥ 断连 → 权限丢失，重连后需重新校验
```

**关键点：运行权限不持久化。** BMS 重启、蓝牙断连、甚至长时间空闲后权限都可能失效。
实现时应把「发起写操作前确保权限足够」作为标准流程，而不是只在连接时校验一次。

### 真机实测补充（2026-09-29，ANT@BLE24CBUB-3547）

- **`0x43` 回的是「当前运行权限」，不是「本次校验结果」**。密码不对时它不会回 0，
  而是把本次连接已经拿到的权限原样返回。实测：先过了二级，再用错误密码去校验三级槽
  → 应答 `func=43 reg=346 len=2 02 00`（= 2，而不是 0）。
  因此**判定必须写成「返回值 ≥ 所校验的等级」**：
  ```kotlin
  val ok = got >= level && got > 0      // 只看 got > 0 会把失败当成功
  ```
  只看 `>0` 的实现在实测中把一个错误的三级密码记成了「已记住」，之后每次连接都白试一轮。
- **权限在同一上电周期内可跨 BLE 断连保持**：实测断连重连（甚至 App 重启）后设备仍报 2 级。
  所以不要假设「重连后一定是 0 级」，应以实时帧偏移 0 的权限字节为准，再决定要不要补校验。
- **实测密码**：一级 `12345678`（槽 330，出厂默认）✓、二级 `25927601`（槽 338）✓；
  三级槽 346 用 `12345678` 校验**不通过**（回当前权限 2）——说明该机三级密码不是默认值。
- **实用姿势**：按设备地址把各级密码存本地，连接后自动挑「已记住的最高级」校验一次，
  失败就把该级密码删掉，避免每次连接都重试错误密码。

## 9.4 读取设备身份（功能码 0x04）

### 请求（短帧）

```
7E A1 04 <ID类型2B 小端> <读取长度> CRC AA 55
```

| 寄存器值 | 类型 | 典型长度 |
|---|---|---|
| `0x0000` (0) | 芯片 ID / 设备 ID | 12 |
| `0x1000` (4096) | 系统 ID 2 | 12 |
| `0x1200` (4608) | 随机码 + 唯一码 | 18 ~ 20 |

示例：

```
读芯片 ID ：7E A1 04 00 00 0C 98 EC AA 55
读系统 ID ：7E A1 04 00 10 0C XX XX AA 55
读随机码  ：7E A1 04 00 12 12 XX XX AA 55     （0x1200 = 4608）
```

> 旧版权限页面同时发这两条（间隔 200 ms）：
> `ReadData(0, 12, 4)` 与 `ReadData(4608, 18, 4)`。

### 应答（长帧）

```
7E A1 14 <ID类型2B> <长度> <数据区> CRC AA 55
```

数据区结构：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 2 | 随机码 | 2 字节，用于防重放/校验；App 以十六进制展示 |
| 2 | L−2 | ID 字符串 | ASCII/UTF-8，去尾部 `0x00` |
| L−2 | 2 | 加密方式 | 仅当长度 > 18 时存在 |

### 两种解码方式

**方式一（新版）**：把偏移 2 开始的内容按字符串解码

```python
text = data[2:L].split(b'\x00')[0].decode('utf-8', 'ignore')
```

示例：数据区 `61 56 47 38 32 38 35 36 50 50 32 4A 36 59 46 36 43 33 02 00`
（来自 `bms_0x14` 的测试向量，寄存器 `0012`）

| 字段 | 值 |
|---|---|
| 随机码 | `61 56` |
| ID 字符串 | `VG82856PP2J6YF6C3` |
| 加密方式 | `02 00` |

**方式二（旧版）**：把每个字节转**十进制**并用 `.` 连接

```javascript
str = str + "." + byte.toString();     // 例如 97.86.71.56...
```

旧版对寄存器 `4096` 的响应存入 `SysID2`，其他存入 `SocId`。
这是两代 App 的差异点之一 —— **同一份数据，两种表示**。

> 对接建议：优先用字符串方式解读（新版做法），
> 十进制点分格式仅在需要与旧版 App 显示一致时使用。

## 9.5 新版权限机制

新版在协议层之上加了一层「设备绑定 + 权限校验」机制：

| 机制 | 说明 |
|---|---|
| 命令码 `2301` ~ `2305` | 写入 1 ~ 5 级密码（功能码 `23` + 寄存器 `01`~`05`） |
| `quick_auth` 命令 | 快速校验权限（命令号 `23`，携带等级参数） |
| 权限弹窗 | 需要写操作时弹出输入密码，校验成功后缓存权限 |
| 采集芯片升级 | 要求权限 ≥ 5，不足时直接拒绝并提示当前权限 |
| 芯片切换 | 同样要求权限 ≥ 5 |

新版还把**权限级别显示**做了友好化（如「五级权限」文案），
但底层仍是 330/338/346/354/362 这五个地址。

## 9.6 实战要点

| 要点 | 说明 |
|---|---|
| **默认密码** | 一级出厂密码通常是 `12345678`，但设备可能已被修改 |
| **密码长度固定 8 字节** | 不足补 `0x00`，不要只发实际长度 |
| **权限会丢失** | 断连、重启后需重新校验 |
| **读参数也需要权限** | 部分固件下权限 < 1 时连参数区都读不到 |
| **连续失败可能锁定** | 部分固件对连续错误密码有冷却，避免暴力尝试 |
| **身份 ID 用途** | 用于设备绑定、云端鉴权、防伪；App 会把 ID 与账号关联 |
| **随机码会变化** | 每次读取可能不同，不要当作固定 ID 缓存 |

### 最小握手序列（写操作前）

```
1. 7E A1 01 00 00 F5 58 62 AA 55        读实时数据，检查权限值
2. 若权限 < 3：
   7E A1 23 4A 01 08 <密码ASCII 8字节> CRC AA 55
   等待 0x43，确认权限值 ≥ 3
3. 执行写操作
```
