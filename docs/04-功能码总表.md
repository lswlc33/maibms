## 4.1 完整功能码表

> 🟠 **实测部分验证**（2026-09-29 同上）：实测走通的功能码对：`01→11`、`02→12`、`22→42`、`23→43`、`51→61`，以及附加段 `FF`；其余（`04`、`13`、`53→63`、`57`、`59/70` 等）未在真机验证。

| 请求 | 响应 | 名称 | 数据区 | 章节 |
|---|---|---|---|---|
| `01` | `11` | 读实时数据 ★ | 单体电压、温度、总压、电流、SOC/SOH、状态位、容量、统计量 | [第 5 章](05-实时数据.md) |
| `02` | `12` | 读参数区 | 请求：起始地址 + 字节数；响应：u16 小端数组 | [第 6 章](06-参数读写.md) |
| `03` | `13` | 读事件日志 | 事件条数 + 事件码 + 时间戳 + 逐条数据项 | [第 8 章](08-日志与事件.md) |
| `04` | `14` | 读身份标识 | 随机码 + ASCII ID 串（+ 加密方式） | [第 9 章](09-权限与身份.md) |
| `05` | `15` | 读保护动作次数 | 20 个 u16 计数器 | [第 8 章](08-日志与事件.md#85-保护动作次数0x05) |
| `06` | `16` | 读 GPS / 定位 | 经纬度、速度、里程、日期时间、SIM/IMSI/IMEI | [第 10 章](10-DTU与GPS.md) |
| `07` | `17` | 读 GPRS / DTU 配置 | 服务器地址、端口、账号、上传开关等 | [第 10 章](10-DTU与GPS.md) |
| `22` | `42` | 写单个参数 | 请求：地址 + 值；响应：结果码 + 回显 | [第 6 章](06-参数读写.md) |
| `23` | `43` | 权限密码校验 / 设置 | 请求：地址 + 8 字节 ASCII；响应：权限等级 | [第 9 章](09-权限与身份.md) |
| `26` | `46` | 写 DTU / 配置项 | 请求：地址 + u16 值 | [第 10 章](10-DTU与GPS.md) |
| `51` | `61` | 控制命令 / 保存 / 从机数据 | 请求：命令号；响应：结果码或从机数据 | [第 7 章](07-控制命令.md) |
| `52` | `62` | 升级数据分包（BMS） | 请求：包序号 + 固件块；响应：回显序号 | [第 12 章](12-固件升级.md) |
| `53` | `63` | DTU / GPS 模块命令 | 请求：命令号；响应：结果码 / 属性串 | [第 10 章](10-DTU与GPS.md) |
| `54` | `64` | 升级数据分包（DTU） | 同 `52` | [第 12 章](12-固件升级.md) |
| `55` | `65` | 升级数据分包（Boot） | 同 `52` | [第 12 章](12-固件升级.md) |
| `56` | `66` | 屏幕升级 / 应用保存 | — | [第 12 章](12-固件升级.md) |
| `57` | `67` | BLE 升级控制 / 保存蓝牙参数 | — | [第 12 章](12-固件升级.md) |
| `59` | `69` | 采集芯片（AFE）命令 | 见 [第 11 章](11-采集芯片与扩展帧.md) | [第 11 章](11-采集芯片与扩展帧.md) |
| `70` | `80` | 采集芯片扩展命令 | 线阻、重启、串数固定、时间校准 | [第 11 章](11-采集芯片与扩展帧.md) |
| `86` | `96` | 充电器（V2 / BLE）升级 | 控制与数据同用 `86` | [第 12 章](12-固件升级.md) |
| `0D` | `1D` | 读调试参数 | 调试/诊断用，1 秒轮询；字段由协议模板定义 | [第 11 章](11-采集芯片与扩展帧.md#118-调试参数0x0d--0x1d) |
| — | `FE` | 扩展信息（机型 / 扩展告警） | 机型识别、扩展标志、湿度、RTC、主动均衡 | [第 11 章](11-采集芯片与扩展帧.md) |
| — | `FF` | 固件升级完成 | 无 | [第 12 章](12-固件升级.md) |

> 表中「请求」列的功能码出现在**手机 → BMS** 方向；「响应」列出现在 **BMS → 手机** 方向。
> 少数功能码可能双向出现（如 `51` 在升级流程中也由设备侧使用），以实际上下文为准。

## 4.2 命名规律

### 规律一：读命令响应 = 请求 + 0x10

```
01 → 11    读实时数据
02 → 12    读参数
03 → 13    读日志
04 → 14    读 ID
05 → 15    读保护计数
06 → 16    读 GPS
07 → 17    读 GPRS 配置
51 → 61    控制命令
53 → 63    DTU 命令
59 → 69    采集芯片命令
70 → 80    采集芯片扩展命令（注意：这条 +0x10 恰好是 0x80）
```

### 规律二：写参数响应 = 请求 + 0x20

```
22 → 42    写单参数
23 → 43    权限
26 → 46    写配置
```

这两组功能码的响应都不带「+0x10」的常规偏移，而是 +0x20，
原因是它们在协议里被归为「写操作」家族，用高半字节显式区分读写语义。

### 规律三：升级家族同样遵循 +0x10

```
52 → 62    BMS 升级数据
54 → 64    DTU 升级数据
55 → 65    Boot 升级数据
56 → 66    屏幕升级 / 保存（应答 66 也可表示"操作成功"）
57 → 67    BLE 升级控制与数据
86 → 96    充电器（V2/BLE）升级
```

**升级功能码不例外，同样 +0x10**。这一点由新版源码直接给出证据：
响应功能码到请求功能码的映射表写作 `{42:"22", 46:"26", 43:"23", 96:"86"}`
（`pages_Detail/mixJs/bleComApi.js`），其中 `96 → 86` 正是 +0x10。

> 注意区分：`86` 既是充电器升级的**控制**功能码也是其**数据**功能码（请求侧同号），
> 但它们对应的**应答**是 `96`。

## 4.3 按数据流向分类

### 手机 → BMS（命令方向）

| 功能码 | 用途 | 帧型 |
|---|---|---|
| `01` `02` `03` `04` `05` `06` `07` | 读命令 | **短帧**（10 字节，长度=读取字节数） |
| `22` `23` | 写参数 / 密码 | 长帧（带数据） |
| `26` | 写配置 | 长帧 |
| `51` | 控制 / 保存 | 短帧（无数据）或长帧（带参数） |
| `52` `54` `55` `56` `57` | 升级数据 | 长帧（大块数据） |
| `53` `59` `70` | 模块 / 采集芯片命令 | 短帧或长帧 |

### BMS → 手机（应答方向）

| 功能码 | 用途 | 备注 |
|---|---|---|
| `11` | 实时数据 | 500 ms 一次，最频繁 |
| `12` `42` | 参数数据 / 写结果 | |
| `13` | 事件日志 | 按请求的日志号返回 |
| `14` | 身份标识 | |
| `15` | 保护计数 | |
| `16` `17` | GPS / GPRS | |
| `43` `46` | 权限 / 配置结果 | |
| `61` `63` | 控制结果 / DTU 结果 | 首字节或前两字节为结果码 |
| `69` `80` | 采集芯片应答 | |
| `FE` | 扩展信息 | 常作为组合帧第二段，跟在 `11` 后面 |
| `FF` | 升级完成 | |

## 4.4 寄存器字段的含义随功能码变化

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：实测：`02`=起始地址、`22`=参数地址、`23`=密码槽地址、`51`=命令号，应答里同字段回带同值。

同一个 2 字节「寄存器」字段，在不同功能码下**含义完全不同**，
而且**字节序也不统一** —— 这是读协议时的重要认知：

| 功能码 | 寄存器字段的含义 | 示例（线上字节） | 字节序 |
|---|---|---|---|
| `01` | 起始地址（读实时数据固定 0） | `00 00` | 小端 |
| `02` | 参数区起始地址（字节偏移） | `68 00` = 104 | 小端 |
| `03` | 日志序号 | `00 00` = 第 0 条 | 小端 |
| `04` | ID 类型：0 芯片ID / 4096 系统ID2 / 4608 随机码+唯一码 | `00 10` = 4096 | 小端 |
| `06` / `07` | 配置区块起始地址 | `74 00` = 116 | 小端 |
| `22` | 要写的参数地址 | `04 00` = 4 | 小端 |
| `23` | 密码等级地址：330/338/346/354/362 | `4A 01` = 330 | 小端 |
| `51` | **命令号**（不是地址） | `06 00` = 命令 6（开充电） | 小端 |
| `52` 等升级 | **包序号** | 递增 | 小端 |
| `53` | **DTU 命令号** | `01 00` = 重启 GPS | 小端 |
| `59` / `70` | 采集芯片命令码（按源码命令名书写） | `00 F0` = 切换芯片；`01 00` = 查询线阻 | **高字节在前** |
| `57`（升级阶段） | 代码型寄存器 `02FF` / `0CF1` / `0DF1` | `0C F1` = 执行 BLE 升级 | **高字节在前** |
| `FE` | 机型区间标识 | 512~767 = 双芯片主动均衡 | 小端 |

> 本表与 [第 3.1 节](03-帧格式与校验.md#寄存器字段的字节序)、[附录 D](附录D-样例报文.md#关于寄存器字段的字节序重要)
> 的三份表内容一致（第 3.1 节为全量权威版本）。
>
> **易错点**：`04` 的 ID 类型值 4096（0x1000）线上是 `00 10`，
> 而 AFE 命令 0x0100 线上是 `01 00` —— 两者写法相似但顺序相反。
> 复用样例报文时务必照抄字节，不要自己「按规律」推。
