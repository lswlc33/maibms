# 附录 D · 样例报文

> 本附录所有报文均由协议规则构造，并用**标准 CRC16-Modbus** 逐条校验通过；
> 其中「读实时数据」「保存应用参数」「写单体过压保护」「密码校验」「采集芯片切换」五条
> 与 App 源码中的常量逐字节一致。
> 直接复制到 nRF Connect 等工具的 Write 框（十六进制模式）即可发送。

### 关于寄存器字段的字节序（重要）

同一个「寄存器」字段，在不同功能码下的**字节顺序并不统一**，这是照着样例报文改参数时最容易出错的地方：

| 功能码 | 字节序 | 例子 |
|---|---|---|
| `01` `02` `03` `04` `06` `07` | **小端**（低字节在前） | 地址 620 → `6C 02`；地址 4096 → `00 10` |
| `22` `23` `26` | **小端** | 地址 330 → `4A 01` |
| `51` | **小端**（命令号通常 <256，低字节在前） | 命令 40 → `28 00` |
| `52`（升级包序号） | **小端** | 第 1 包 → `01 00` |
| `53`（DTU 命令） | **小端** | 命令 1 → `01 00` |
| `70` `80`（AFE 扩展） | **高字节在前** | 命令 0x0100 → `01 00`；0x0300 → `03 00` |
| `59`（AFE 主指令） | **高字节在前** | 命令 0x00F0 → `00 F0` |
| `57`（BLE 升级阶段） | **高字节在前** | 代码 `0CF1` → `0C F1` |
| `FE`（机型区间） | **小端** | 512 → `00 02` |

> 与 [第 3.1 节](../03-帧格式与校验.md#寄存器字段的字节序)、[第 4.4 节](../04-功能码总表.md#44-寄存器字段的含义随功能码变化)
> 的表格内容一致（第 3.1 节为全量权威版本）。

> AFE 命令的字节序依据：App 源码里用 `new Uint8Array([1, 0])` 表示命令 `0x0100`、
> `new Uint8Array([6, 0])` 表示 `0x0600`，其测试向量的寄存器参数写作 `"06 00"`；
> 采集芯片切换命令的常量帧为 `7EA0 59 00 F0 01 10 04D9 AA55`。
> 即以「源码中的命令名」书写时，高字节在前。

### 关于 35~36 号（十二字节密码槽）

这两条演示**长密码槽**的写法：寄存器 = 槽起始地址（362 / 374 小端），**长度 = `0C`（12 字节）**：

```
7E A1 23 6A 01 0C | 31 32 33 34 35 36 37 38 39 30 31 32 | CRC | AA 55
         └─┬─┘ └┬┘   └─────── "123456789012" 的 ASCII ──────┘
     362 = 0x016A 长度 12
```

- **35 号**：五级密码，12 字节 ASCII（不足补 `0x00`）。
- **36 号**：管理员密码，数据是**点分十进制逐段转成的字节**（示例用 `1.2.3.4.…12` → `01 02 03 … 0C`）。

> 一~四级密码槽是 **8 字节**，样例见 27/28 号；密码区完整布局见 [第 9.1 节](../09-权限与身份.md#91-五级权限体系)。

### 关于 32~34 号（BLE 升级三连）

这三条是**按源码的组帧规则构造**的示例（功能码 `57`、寄存器代码高字节在前、无数据区）：

```
7E A1 57 0C F1 00 | CRC | AA 55
      └┬┘ └─┬─┘ └┬┘
    功能码 57  代码 0CF1 长度 0
```

> ⚠ **两点须知**：
> ① 功能码 `57` 是 App 侧常量（升级类型表 `sendPackageFun`），但**前缀与期望应答功能码来自服务端协议模板**；
> ② 这三条命令**不要随便试** —— 在未按正确流程缓存固件前发送 `0CF1`，
> 设备会因「蓝牙缓存固件无效」而失败（返回状态码 `00`），浪费一次升级机会。
> 仅供理解帧结构，实际升级请走完整流程（见 [第 12.4 节](../12-固件升级.md#124-新版流程ble-升级)）。

### 使用提示

- 前 3 条（读实时数据）任选一条先发，收到 `7E A1 11 ...` 即说明链路与协议都通。
- 控制类命令（`0x51`）执行前建议先确认权限（读实时数据看数据区偏移 0 的值）。
- 写参数（`0x22`）后必须发**保存应用参数**（`7EA15107000038E4AA55`）才写入 flash。
- AFE 命令（`0x59` / `0x70`）需要 5 级权限。

## D.2 CRC 计算说明

以「读实时数据 245 字节」为例（短帧）：

```
帧内容：7E A1 01 00 00 F5 | CRC_L CRC_H | AA 55

CRC 覆盖范围：A1 01 00 00 F5        （地址 → 长度，共 5 字节）
crc16_modbus("A1010000F5") = 0x6258
线上字节顺序：低字节在前 → 58 62

最终帧：7E A1 01 00 00 F5 58 62 AA 55
```

长帧的差别只在覆盖范围（多算数据区）：

```
「写单体过压保护 = 3.650V」：
帧内容：7E A1 22 04 00 02 42 0E | CRC_L CRC_H | AA 55
CRC 覆盖：A1 22 04 00 02 42 0E    （7 字节）
crc16_modbus(...) = 0x2C4C  →  线上 4C 2C
```

> 覆盖范围速记：**从地址字节开始，到最后一个数据字节结束**。
> 不含帧头 `7E`，不含帧尾 `AA 55`，也不含 CRC 自身。
> CRC 本身**始终**低字节在前（不看寄存器字段的字节序）。

## D.3 应答样例结构

设备应答的字节内容随电池状态变化，此处给出结构：

### 实时数据应答（0x11）

```
7E A1 11 00 00 <N> <N 字节数据> CRC_L CRC_H AA 55
      └┬┘ └┬┘
   功能码 11 │
             └── 数据长度（典型 146 ~ 186，取决于串数/温度数/固件版本）
```

数据区解码见 [第 5 章](../05-实时数据.md)。

### 参数应答（0x12）

```
7E A1 12 <地址2B 小端> <长度> <长度 字节的 u16 小端数据> CRC AA 55
```

### 写参数应答（0x42）

```
7E A1 42 <地址2B> <长度> <结果码1B> [...] CRC AA 55
```

`结果码 = 01` 即成功。

### 控制应答（0x61）

```
7E A1 61 <命令号2B> <长度> <结果码1B> [...] CRC AA 55
```

### 组合帧（实时 + 扩展）

```
7E A1 11 00 00 <N> <数据> CRC1 | FE <机型寄存器2B> <长度> <数据> CRC2 | AA 55
                                └────────────────────────────────────┘
                                  第二段：无帧头，独立 CRC
```

拆分规则见 [第 3.3 节](../03-帧格式与校验.md#33-组合帧)。
