## 13.3 MOS 状态与均衡状态

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：实测字节位置与取值（`1`=开启、`0`=关闭）与本文一致。

来源：实时数据尾部相对偏移 12（放电 MOS）、13（充电 MOS）、14（均衡状态），各 1 字节。

> **两版用法不同**：新版界面上的「MOS 是否开启」其实是看**告警位 18 / 19**
> （源码 `topInfo.js` 用 `warnBit.indexOf(18)` 判定充电 MOS、`indexOf(19)` 判定放电 MOS），
> 而下面的状态字节则作为「状态码」用于展示（`== 1` 表示开启）。
> 旧版直接用状态字节映射成文案。两者结合看最稳妥：
> **是否开启看状态字节 == 1，为什么断开看状态码文案**。

> **表的来源**：下面三张状态表取自**旧版** `AntDict.CH_MOS_State` / `DIS_MOS_State` / `Balance_State`。
> 新版没有再维护同名表（只做 `== 1` 判断），因此这三张表是目前唯一可用的状态码字典，
> 但**未在真机上逐项验证过**，遇到超出表范围的取值请按「保留」处理。

### 充电 MOS 状态（偏移 13）

| 值 | 含义 | 值 | 含义 |
|---|---|---|---|
| 0 | 关闭 | 12 | 开启失败 |
| 1 | **开启** | 13 | 放电管异常 |
| 2 | 单体过压 | 14 | 等待 |
| 3 | 过流保护 | 15 | 手动关闭 |
| 4 | 电池充满 | 16 | 二级过压 |
| 5 | 总压过压 | 17 | 低温保护 |
| 6 | 电池过温 | 18 | 压差超限 |
| 7 | 功率过温 | 20 | 自检异常 |
| 8 | 电流异常 | 21 ~ 31 | 保留 |
| 9 | 均衡线掉串 | | |
| 10 | 主板过温 | | |
| 11 | （保留） | | |

### 放电 MOS 状态（偏移 12）

| 值 | 含义 | 值 | 含义 |
|---|---|---|---|
| 0 | 关闭 | 11 | 充电开启 |
| 1 | **开启** | 12 | 短路保护 |
| 2 | 单体欠压 | 13 | 放电管异常 |
| 3 | 过流保护 | 14 | 开启失败 |
| 4 | 二级过流 | 15 | 手动关闭 |
| 5 | 总压欠压 | 16 | 二级欠压 |
| 6 | 电池过温 | 17 | 低温保护 |
| 7 | 功率过温 | 18 | 压差超限 |
| 8 | 电流异常 | 19 | 自检异常 |
| 9 | 均衡线掉串 | 20 ~ 31 | 保留 |
| 10 | 主板过温 | | |

> 这两个表的语义不是「MOS 当前开关状态」那么简单 ——
> 值 2~13 等表示「MOS 因某原因被断开」，是诊断故障的关键信息。
> 例如读到「14 开启失败」说明 BMS 想开但没成功，通常是 MOS 损坏或线路问题。

### 均衡状态（偏移 14）

**旧版**把它当作取值 0~15 的状态码，用下表映射（`AntDict.Balance_State`）：

| 值 | 含义 |
|---|---|
| 0 | 关闭 |
| 1 | 极限均衡 |
| 2 | 充电压差 |
| 3 | 均衡过温 |
| 4 | 自动均衡 |
| 5 | 手动平衡 |
| 6 ~ 15 | 保留 |

**新版**只把它当「是 / 否」用（源码里映射表就是 `["否","是","是","是","是","是"]`），
详细的均衡模式改为从**告警位**读取（位 27 均衡极限、28 均衡压差、29 均衡自动、30 均衡过温、25 均衡开）。

> 两版对这一字节的**宽度**理解也不同：旧版按 2 字节 u16 读（会把紧跟其后的 `bmsType` 并进来），
> 新版按 1 字节 + 1 字节（`equilibriumState` + `bmsType`）读。两者占用的总长度相同（4 字节）。
> 自研实现建议按新版：**只取 1 字节状态 + 1 字节 bmsType**。

## 13.5 电池类型

> ✅ **实测已验证**（2026-09-29 · 真板 `ANT@BLE24CBUB-3547`，固件 `24CBUB02-240623C`）：实测 `0xFAF1` = 三元锂。

来源：

- 实时数据尾部相对偏移 60（u16，`batteryType`）
- 参数区地址 152（`packCellType`）

**值是 `0xFAFx` 形式的编码，不是 1/2/3 这种小整数**（这点极易踩坑）：

| 值 | 十进制 | 含义 |
|---|---|---|
| `0xFAF1` | 64241 | 三元锂 |
| `0xFAF2` | 64242 | 磷酸铁锂 |
| `0xFAF3` | 64243 | 钛酸锂 |
| `0xFAF6` | 64246 | 钠电 |
| `0xFAF7` | 64247 | 磷酸锰铁锂 |
| 其他 | — | 未设置 / 未知 |

> 旧版 App 的参数页面用 `datatype` + 下拉列表直接写小整数（1/2/…），
> 新版权威值是 `0xFAFx`。若你读到的参数值是 1~6 之类的小整数，
> 说明该固件使用旧编码，建议按「同一设备上两种编码保持一致」的原则处理。

### 电池类型预设命令

一键套用某类型的推荐阈值组合：

| 命令号（功能码 51） | 类型 |
|---|---|
| 38 | 钛锂参数 |
| 39 | 三元参数 |
| 40 | 铁锂参数 |
| 53 | 钠电参数 |

## 13.6 机型（bmsModel）

来源：扩展帧 `0xFE` 的寄存器区间。

| 寄存器区间 | 机型标识 | 中文 | 主动均衡 |
|---|---|---|---|
| 512 ~ 767 | `double_balance` | 双芯片主动均衡 | ✔ |
| 768 ~ 1023 | `low_cost` | 低成本 | ✘ |
| 1024 ~ 1279 | `home_store` | 家储 HDA | ✔ |
| 1280 ~ 1535 | `swap_ele` | 换电 RDA | ✔ |
| 1536 ~ 1791 | `car_starting` | 汽车启动 TDA | ✔ |

## 13.7 主动均衡机型判定

`bmsType` 是实时数据尾部相对偏移 15 的 1 字节，规则如下：

```
bmsType == 1   →  主动均衡机型
bmsType == 2   →  主动均衡机型
bmsType == 33  →  由机型表决定：
                    若扩展帧给了 activeBal 布尔值 → 用它
                    否则查表：double_balance/home_store/swap_ele/car_starting/amd = true
                             low_cost = false
其他值          →  非主动均衡机型
```

参考实现：

```python
MODEL_ACTIVE = {
    "double_balance": True, "low_cost": False, "home_store": True,
    "swap_ele": True, "car_starting": True, "amd": True,
}

def is_active_bal(bms_type: int, bms_model: str = None, active_bal=None) -> bool:
    if bms_type in (1, 2):
        return True
    if bms_type == 33:
        if isinstance(active_bal, bool):
            return active_bal
        return MODEL_ACTIVE.get(bms_model, False)
    return False
```

**为何重要**：该判定决定实时数据尾部相对偏移 36 的 4 字节如何解读：

| 判定 | 4 字节含义 |
|---|---|
| 非主动均衡 | 均衡位图（bit i = 第 i+1 串在均衡） |
| 主动均衡 | 结构体：均衡序号 / 线阻 / 均衡电流 / 故障码 |

另外，**均衡电流的缩放也与 bmsType 相关**：

```
bmsType 为 2 或 33  →  均衡电流 ÷10
其他               →  均衡电流 ÷100
```
