## 11.1 采集芯片（AFE）是什么

采集芯片（Analog Front End）负责：

- 逐串采集单体电压
- 驱动被动/主动均衡
- 测量均衡线内阻与温度
- 自身可独立升级（Boot 模式）

在协议里它有两个特点：

1. **使用独立地址 `A0`**（BMS 主控是 `A1`）
2. 有**自己的指令族**：功能码 `59`（主指令）与 `70`（扩展指令）

```
手机 ──BLE──▶ BMS 主控(A1) ──内部总线──▶ 采集芯片(A0)
                    │
                    └── 转发手机发来的 A0 帧
```

## 11.2 AFE 主指令（0x59 → 0x69）

### 帧格式

```
7E A0 59 <命令码2B 小端> <长度> <数据> CRC AA 55
     └┬┘
   地址 A0 = 采集芯片
```

### 已知命令

| 命令码 | 名称 | 参数 | 说明 |
|---|---|---|---|
| `00F0` | 切换采集芯片 | 1 字节 | 选择要操作的采集芯片通道 |
| `0000` 起 | 获取采集芯片软件版本号 | — | 读取 AFE 固件版本 |

### 实例：切换采集芯片通道

```
7E A0 59 00 F0 01 10 04 D9 AA 55
         └─┬─┘ └┬┘ └┬┘
    命令码 0x00F0 │   └── 参数 0x10
            长度 = 1
```

解析：

| 字段 | 值 |
|---|---|
| 地址 | `A0`（采集芯片） |
| 功能码 | `59` |
| 命令码 | `0x00F0`（小端存 `00 F0`） |
| 长度 | 1 |
| 参数 | `0x10` |
| CRC | `04 D9`（标准 Modbus 算得 0xD904，低字节在前） |

### 应答（0x69）

新版用命令名 `changeChipsN` 区分多个通道，应答功能码 `69`。

**判定方式**：新版不解析固定结果码，而是把应答交给协议模板判读 ——
只要解析结果里出现名字含 `_success` 的字段即视为成功
（同样要求权限 ≥ 5，不足时 App 会直接拒绝，见下节）。

### 使用门槛

| 操作 | 最低权限 |
|---|---|
| 切换采集芯片 | 5 |
| 升级采集芯片 | 5 |

新版会在权限不足时直接拒绝，并提示当前权限值。
部分机型（`amd` 分口板）的芯片切换还与机型相关，会显示不同文案。

## 11.3 AFE 扩展指令（0x70 → 0x80）

### 帧格式

```
7E A1 70 <命令码2B 高字节在前> [数据] CRC AA 55          请求
7E A1 80 <命令码2B 高字节在前> <长度> <数据> CRC AA 55   应答
```

### 命令码表

| 命令码（源码命名） | 线上字节 | 命令名 | 中文 | 用途 |
|---|---|---|---|---|
| `0x0100` | `01 00` | querylineResistance | 查询线阻 | 测量各串均衡线内阻（UI 标签「第 N 串线阻」，**不显示单位**） |
| `0x0300` | `03 00` | restartChipPower | 重启采集芯片电源 | 复位 AFE |
| `0x0400` | `04 00` | fixToCount | 固定到指定串数 | 锁定采集串数 |
| `0x0600` | `06 00` | cellSumVoltRpt | 单体累加总压上报 | 读取各串累加电压 |
| `0x0700` | `07 00` | fixTime | 校准时间 | 写 RTC 时间 |

> **⚠ 字节序提醒**：AFE 命令码按源码命名书写时是**高字节在前**
> （`0x0100` → 线上 `01 00`），与读命令的地址字段（小端）相反。
> 依据是 App 源码用 `new Uint8Array([1, 0])` 表示命令 `0x0100`、
> `new Uint8Array([6, 0])` 表示 `0x0600`，其测试向量的寄存器参数写作 `"06 00"`。

### 各命令的应答解析

#### `0x0100` 查询线阻

```
数据区：[0] 数量 K，其后 K × 2 字节（每 2 字节一个 u16 线阻值）
```

| 字段 | 提取 | 说明 |
|---|---|---|
| number | `data[0]` | 有效串数 |
| lineResistances | 从 `data[1]` 起按 2 字节切分 | u16 数组；App 只做 ÷100 后直接显示，**界面上不带单位** |

> **单位推断**：解析器对每个值做了 ÷100，而 App 的调试功能页显示时 `unit` 为空字符串
> （`buildChildList` 里写死 `unit: ""`），所以单位只能从量级推断：
> 常见均衡线/汇流电阻在 0.1~2 mΩ 量级，若原始值形如 50 → 0.5，则单位应为 **mΩ**（原始值以 0.01 mΩ 为单位）。
> 这仍是推断，建议用万用表实测一条已知线阻后反推系数。

```python
def parse_line_resistance(d: bytes):
    n = d[0]
    vals = [d[1+2*i] | (d[2+2*i] << 8) for i in range(n)]
    return {"number": n, "lineResistances": vals}
```

#### `0x0300` 重启采集芯片 / `0x0400` 固定到指定串数

```
数据区：[0] 状态码
```

| 状态码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 权限不足 |
| 2 | 失败 |

#### `0x0600` 单体累加总压上报

```
数据区：[0] 数量 K，[1..2] 错误码 u16，[3..] K × 2 字节电压
```

| 字段 | 提取 | 说明 |
|---|---|---|
| number | `data[0]` | 有效串数 |
| errorCode | `u16(data, 1)` | 0 = 无错误 |
| vols | 从 `data[3]` 起按 2 字节切分 | u16 数组 |

#### `0x0700` 校准时间应答

```
数据区：[0] 状态码
```

| 状态码 | 含义 |
|---|---|
| 0 | 成功 |
| 2 | 数据长度不是 4 |
| 3 | 时间戳无效或超出 RTC 支持范围 |
| 4 | 不支持的扩展地址 |

### 完整示例

App 内置测试向量：数据区 `01 65 00 90 01 20 03 B0 04 40 06`，命令码 `06 00`（`0x0600`）

| 字段 | 值 |
|---|---|
| 数量 | `0x01` = 1 |
| 错误码 | `0x0065` = 101 |
| 电压数组 | `0x0190`(=400), `0x2003`, `0xB004`, `0x4006`（合成数据） |

> 该向量是厂商构造的，数值本身无意义，主要用于验证字段切分逻辑。

## 11.4 扩展信息帧（0xFE）

### 出现形式

`0xFE` **通常不作为独立帧出现**，而是作为**组合帧的第二段**跟在实时数据 `0x11` 后面：

```
7E A1 11 ... CRC1 | FE <寄存器2B> <长度> <数据> CRC2 AA 55
                    └───────────────────────────────────┘
                          第二段（无帧头）
```

组合帧的拆分规则见 [第 3.3 节](03-帧格式与校验.md#33-组合帧)。
新版 App 的另一种解析路径是：在 `0x11` 数据区之后按「额外段」继续读取，
用同样的组合帧思路处理（`bleDeal.js` 中的 `bms_0xfe_100().analysis(...)`）。

### 作用一：机型识别（最重要）

**第二段的寄存器值落在哪个区间，就代表哪种硬件方案**：

| 寄存器区间 | 机型标识 | 中文 | 主动均衡 |
|---|---|---|---|
| 512 ~ 767 | `double_balance` | 双芯片主动均衡 | ✔ |
| 768 ~ 1023 | `low_cost` | 低成本方案 | ✘ |
| 1024 ~ 1279 | `home_store` | 家储 HDA | ✔ |
| 1280 ~ 1535 | `swap_ele` | 换电 RDA | ✔ |
| 1536 ~ 1791 | `car_starting` | 汽车启动 TDA | ✔ |
| 1792 ~ 2047 | `amd` | 分口板 AMD | ✔ |

解析输出中会同时给出两个关键字段：

```json
{ "bmsModel": "low_cost", "activeBal": false, ... }
```

> **为什么要识别机型**：同一个 4 字节字段在不同机型下含义不同
> （普通均衡位图 vs 主动均衡结构体，见 [第 5.7 节](05-实时数据.md#57-主动均衡结构体)）；
> 界面是否需要显示「主动均衡」页、是否允许芯片切换也都取决于机型。

### 作用二：承载扩展状态

各机型的数据区字段：

> 下表已与 `bms_0xfe_1.0.0.js` 里的字段描述符逐项核对
> （偏移、长度、类型、倍率与源码一致）。

#### 通用（所有机型）

| 偏移 | 长度 | 字段 | 字段标识 | 解码 |
|---|---|---|---|---|
| 0 | 2 | 扩展保护标志 | `extraPf` | u16 |
| 2 | 4 | 扩展告警标志 | `extraWf` | u32 |

#### `double_balance`（追加）

| 偏移 | 长度 | 字段 | 字段标识 | 解码 |
|---|---|---|---|---|
| 6 | 4 | 高边均衡标志位 | `highEfb` | u32，按主动均衡结构体解析（见 [11.6 节](#116-主动均衡解析)） |

#### `home_store`（追加）

| 偏移 | 长度 | 字段 | 字段标识 | 解码 |
|---|---|---|---|---|
| 6 | 4 | RTC 时间 | `rtc` | u32（Unix 秒） |

#### `swap_ele`（追加）

| 偏移 | 长度 | 字段 | 字段标识 | 解码 |
|---|---|---|---|---|
| 6 | 2 | 湿度 | `humidity` | u16 **÷10**，单位 %RH |

#### `car_starting` / `amd` / `low_cost`

仅通用字段（保护标志 + 告警标志）。

## 11.5 六种机型

> 机型标识（`low_cost` 等）与下表的「机型」列中文名，**都直接取自源码**：
> `sdk/api/custom_analyze/bms_0xfe_1.0.0.js` 的机型表里同时定义了
> `name`（英文标识）、`desc`（中文名，如「低成本方案」「家储HDA」「分口板AMD」）
> 和 `activeBal`（是否支持主动均衡）三个字段。仅「典型应用」「特征」两列是本书的推断说明。

| 机型 | 标识 | 典型应用 | 特征 |
|---|---|---|---|
| 低成本 | `low_cost` | 两轮车、储能 | 单芯片，无主动均衡，成本优先 |
| 双芯片主动均衡 | `double_balance` | 高端储能 | 高边+低边双芯片，支持主动均衡 |
| 家储 | `home_store` | 家庭储能 | 带 RTC，支持主动均衡 |
| 换电 | `swap_ele` | 换电柜 | 带湿度检测，支持主动均衡 |
| 汽车启动 | `car_starting` | 汽车启动电源 | 大电流，支持主动均衡 |
| 分口板 | `amd` | 分口应用 | 充放电分口，芯片切换有特殊文案 |

机型会影响：

- 实时数据中「均衡标志位」4 字节的解读方式
- 是否展示主动均衡界面
- 采集芯片切换的可用性与提示文案
- 扩展告警位的存在与否

## 11.6 主动均衡解析

主动均衡机型的 4 字节结构体（来自实时数据或 `0xFE` 帧）：

```
字节 3        字节 2         字节 1           字节 0
┌──────────┬────────────┬──────────────┬────────────┐
│ 均衡序号  │ 线阻 ÷100   │ 均衡电流(s8)   │ 故障码     │
└──────────┴────────────┴──────────────┴────────────┘
```

| 字段 | 提取 | 解码 |
|---|---|---|
| 均衡序号 | `(v >> 24) & 0xFF` | 当前正在均衡的串号（0 = 无） |
| 线阻 | `(v >> 16) & 0xFF` | ÷100，单位 mΩ |
| 均衡电流 | `(v >> 8) & 0xFF` 按 s8 | 机型相关：bmsType `2`/`33` → ÷10，其余 ÷100，单位 A |
| 故障码 | `v & 0xFF` | 0 = 正常 |

完整参考实现见 [第 5.7 节](05-实时数据.md#57-主动均衡结构体)。

> **判断是否主动均衡机型**需要两条信息：
> 1. `bmsType`（实时数据尾部相对偏移 15）
> 2. 扩展帧给出的 `bmsModel` / `activeBal`
>
> 新版实现是二者结合判断（`isActiveBalBoard(bmsType, bmsModel, activeBal)`），
> 只凭单一字段可能误判。

## 11.7 扩展帧的解析入口

扩展帧 `0xFE` 有两种到达方式，实现时都要处理：

| 方式 | 形态 | 处理 |
|---|---|---|
| 组合帧 | 跟在 `0x11` 之后的**第二段**（无帧头） | 按 [第 3.3 节](03-帧格式与校验.md#33-组合帧) 拆第二段 |
| 独立帧 | 以 `7EA1 FE …` 单独到达 | 按普通长帧解析，寄存器即机型区间 |

新版源码里两条路径都有：
`pages_Detail/mixJs/bleDeal.js` 在实时帧之后顺带取机型信息，
而 `utils/dealBle.js` 则用 `simpleUnpackage` 拆出第二段再交给 `bms_0xfe_100` 分析器。

> 判据速记：**先看有没有 `FE` 起始的第二段**；没有则看后面是否跟着独立的 `7E A1 FE`。

## 11.8 调试参数（0x0D → 0x1D）

新版还有一个文档中少见的功能码对，用于**读取设备内部调试参数**：

| 方向 | 功能码 | 说明 |
|---|---|---|
| 请求 | `0D` | 命令名 `debugParamRead`，寄存器与长度由协议模板定义 |
| 应答 | `1D` | 寄存器 `0x0000`，事件通道名为 `notifylisten1d0000` |

### 使用方式

```
① 构建命令：buildCommand("0D", "debugParamRead")
② 发送并等待：publishMessageWait(cmd, "1D", "读取调试参数")
③ 之后每 1000 ms 重发一次（setInterval(..., 1e3)）
④ 收到 0x1D 应答后交给协议模板解析
⑤ 离开页面时清除定时器并注销事件
```

### 数据内容

字段由**服务端协议模板**定义，离线源码中看不到明细，只能确认其中包含两个**位域字段**：

| 字段 | 含义 | 处理方式 |
|---|---|---|
| `doStatus` | 数字输出（DO）状态 | 按位拆分（源码 `parseBits(v, "doStatus")`） |
| `diStatus` | 数字输入（DI）状态 | 按位拆分（源码 `parseBits(v, "diStatus")`） |

其余为具名调试参数，逐个填入页面表格。

> **与旧版 debug 页面的区别**：旧版的 `pages/debug` 只是**通信计数调试** ——
> 不停地读实时数据（`ReadData(0,156,1)`），显示收发包计数（`debug_status_send1~3` 等）；
> 新版的调试参数才是真正读取设备内部状态。
>
> **实现提示**：由于字段名与位定义都在服务端，自研客户端只能先原样透传十六进制，
> 或抓一次官方 App 的应答与界面显示做字段对照。

## 11.9 实战要点

| 要点 | 说明 |
|---|---|
| **AFE 帧地址是 A0** | 解析时不要死认 `A1`；过滤条件建议用「功能码 + 帧尾」而非固定前缀 |
| **功能码 59/69 与 70/80 是两套** | 59 用于芯片切换与版本，70 用于线阻/复位/校时 |
| **权限门槛高** | AFE 操作需要 5 级权限 |
| **0xFE 不是独立帧** | 务必按组合帧规则拆分，否则永远找不到帧头 |
| **机型必须识别** | 决定均衡字段语义，误判会显示错误的均衡状态 |
| **扩展告警位表未公开** | `0xFE` 的保护/告警标志位含义未在代码中出现对照表，App 仅透传 |
| **线阻单位需标定** | AFE 返回的线阻原始值单位与硬件相关，建议与万用表实测值比对后再定系数 |
