## 8.1 事件日志读取（0x03 → 0x13）

### 请求（短帧）

```
7E A1 03 <日志序号2B 小端> 00 CRC AA 55
```

- 功能码 `03`
- 寄存器 = **日志序号**（从 0 开始递增；每读一条，序号 +1）
- 长度 = `00`

示例：读第 0 条日志

```
7E A1 03 00 00 00 99 9D AA 55
```

### 应答（长帧）

```
7E A1 13 <日志序号回显> <长度> <数据区> CRC AA 55
```

BMS 按「序号」逐条返回历史记录，**一次一条**。
新版 App 的做法：请求序号 = **已获取的日志条数**（因此是连续递增的），
并按**每批 10 条**分页加载 —— 源码里的判断是 `logList.length < 10 * logIndex` 时继续取下一批。
读到返回条数为 0（或达到期望页数）即停止。

## 8.2 日志记录结构

数据区布局：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 2 | 日志序号 | 回显请求的序号 |
| 2 | 1 | **事件条数 K** | 本条记录携带的数据项个数 |
| 3 | 1 | **事件类别码** | 查 [8.4 节](#84-事件类别表) 事件表 |
| 4 | 4 | 时间戳 | u32 秒（Unix 时间戳），可转为日期 |
| 8 | 4×K | 数据项 | 每项 4 字节，见下 |

### 数据项（每项 4 字节）

```
┌──────────┬──────────┬───────────────┐
│ 数据项号  │ 符号标志  │ 值 (u16 小端)  │
│  1 字节   │  1 字节   │   2 字节       │
└──────────┴──────────┴───────────────┘
```

| 字段 | 说明 |
|---|---|
| **数据项号** | 1 ~ 32，查 [8.3 节](#83-数据项表32-项) 得到名称与倍率 |
| **符号标志** | `0x80` = 该值为**有符号**（需按 s16 解读）；其他值 = 无符号 |
| **值** | u16 小端；工程量 = 值 ÷ 倍率 |

解析伪代码：

```python
def parse_log_item(buf, off):
    item_id = buf[off]
    sign_flag = buf[off + 1]
    raw = buf[off + 2] | (buf[off + 3] << 8)
    if sign_flag == 0x80 and raw >= 0x8000:
        raw -= 0x10000                       # 有符号
    name, ratio = DATA_ITEMS.get(item_id, ("未知数据项", 1))
    return {"name": name, "value": raw / ratio}
```

> App 的处理顺序是先读数据项号，再读符号标志，再读 2 字节值；
> 遇到未知数据项号时把**数据项号本身**作为值显示（用于固件新增项时兜底）。

## 8.4 事件类别表

事件类别码从 1 开始，完整 133 项见 [附录 C](附录C-事件与日志表.md)。核心区间：

| 区间 | 内容 |
|---|---|
| 1 ~ 16 | 电池类型未设置、各类保护/恢复（过压、欠压、压差、高低温） |
| 17 ~ 32 | MOS 高温、过流、短路、二级保护等保护与恢复 |
| 33 ~ 46 | 控制开关动作、均衡线掉串、电流异常、MOS 异常、内部通信异常 |
| 47 ~ 62 | 各类告警（单体、总压、温度、MOS、过流、SOC、效验异常） |
| 63 ~ 83 | 运行状态（预充失败、充满、充电中、放电中、充电器连接、MOS 开、均衡开、待机、复位、升级、关机、启动、充电结束） |
| 84 ~ 89 | 模组失联、验证九级权限、验证可用时间、恢复参数/厂家参数、保存应用参数 |
| 90 ~ 133 | 保留（固件扩展用） |

**成对记忆**：多数保护类事件是「保护」与「恢复」成对出现的相邻编号，
例如 `2` 单体过压保护 / `3` 单体过压恢复。

## 8.5 保护动作次数（0x05）

### 请求 / 应答

```
请求：7E A1 05 00 00 00 CRC AA 55      （读 20 个计数器）
应答：7E A1 15 00 00 <长度> <20×u16> CRC AA 55
```

### 计数器顺序

数据区为 20 个连续 u16（小端），依次为：

| # | 计数器 | # | 计数器 |
|---|---|---|---|
| 0 | 单体过压保护 | 10 | 充电过流保护 |
| 1 | 总压过压保护 | 11 | 放电过流保护 |
| 2 | 单体欠压保护 | 12 | 短路保护 |
| 3 | 总压欠压保护 | 13 | 充电次数 |
| 4 | 单体压差保护 | 14 | 循环次数 |
| 5 | 电池高温充电保护 | 15 | 低压关机次数 |
| 6 | 电池高温放电恢复 | 16 | 电流异常次数 |
| 7 | 功率管高温保护 | 17 | 手动复位次数 |
| 8 | 电池低温充电保护 | 18 | 看门狗复位次数 |
| 9 | 电池低温放电保护 | 19 | 异常复位次数 |

> **名称来源**：上表按**旧版**解析器里的字段名翻译（`CELL_OV_ProtectNum`、`PACK_OV_ProtectNum`…
> `AbnormalReset`），顺序即数据区顺序 —— 这是目前唯一可依据的来源，未在真机逐项验证。
> 新版对应功能由协议模板解析，离线看不到字段名。
>
> 这套计数器与「清零保护次数」命令（`51/37`）配合使用。
> 用途：判断电池经历过多少次异常，评估健康度。

## 8.6 解析示例

假设收到这样一条日志应答（数据区部分）：

```
02 00            日志序号 = 2
03               事件条数 K = 3
02               事件类别码 = 2（单体过压保护）
6E 5C 3F 68      时间戳 = 0x683F5C6E = 1748986990 → 2025-06-04 03:03:10
0A 00 78 0E      数据项：10 = 最大单体电压，无符号，0x0E78 = 3704 → 3.704 V
01 00 84 03      数据项：1 = 总压，无符号，0x0384 = 900 → 90.0 V
03 00 4A 00      数据项：3 = SOC，无符号，0x004A = 74 → 74 %
```

解读：在第 2 条日志里记录了一次「单体过压保护」事件，
发生时最大单体电压 3.704 V、总压 90.0 V、SOC 74%。

> 这条记录的价值在于：可以看出保护动作是「单体电压触发」而不是总压触发，
> 结合 SOC 还能判断是否是充电末期均衡不良导致。

## 8.7 实战要点

| 要点 | 说明 |
|---|---|
| **读日志不暂停轮询** | 日志用独立功能码 `0x13` 并回显序号，与轮询可共存；不必为读日志停轮询 |
| **序号从 0 开始** | App 从 0 递增读取，返回条数为 0 时停止 |
| **日志条数有上限** | 设备侧环形存储，读到的条数取决于固件配置 |
| **时间戳为 Unix 秒** | 需自行转本地时间（设备可能未校时，时间不一定准） |
| **数据项数可变** | 同一种事件在不同固件里携带的数据项可能不同，按 K 循环读即可 |
| **旧版另有一套解析** | 旧版把同一帧按 `SyslogEventType` / `SyslogDataItem` 两张表解析，与新表基本一致，仅个别文案不同 |
