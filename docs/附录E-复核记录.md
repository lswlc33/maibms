## E.2 已修正的错误（28 项）

### ① 写参数应答（0x42）的语义 —— 影响最大的一处

| | 内容 |
|---|---|
| **原稿** | `0x42` 数据区首字节是结果码 |
| **实际** | `0x42` 数据区是**参数数据块**（布局同 `0x12`）；`0x22` 的写入结果由同一帧追加的 **`0xFF` 段**携带 |
| **依据** | 旧版 `app.js` 的解析函数入口写明 `if (18 == e[2] \|\| 66 == e[2])`（`0x12` 与 `0x42` 共用同一解析分支），失败提示由 `A()` 从 `0xFF` 段读取结果码、参数地址与限值 |
| **修正位置** | [第 6.4 / 6.5 节](06-参数读写.md#64-写参数0x22--0x42)、[附录 B.3](附录B-命令码表.md#b3-写参数结果码0xff-附加段)、[第 15.4 节](15-实战与调试指南.md#154-常见陷阱与排查) |

### ② 控制结果码（0x61）的取值表

| | 内容 |
|---|---|
| **原稿** | 2 = 小于最小值、3 = 大于最大值、5 = 权限不足 |
| **实际** | 1 成功 / 2 失败 / 3 权限不足 / 4 地址超限 / 5 电池类型错误 / 6 电芯信息错误 / 7 固件不匹配 |
| **依据** | 新版 `handleSetParamsResult` 的 `"61"` 分支与旧版 `app.js` 的 `h()` 完全一致；原稿误把「写参数码表」套用到了 `0x61` 上 |
| **修正位置** | [第 7.3 节](07-控制命令.md#73-应答与结果码)、[附录 B.2](附录B-命令码表.md#b2-控制结果码0x61-应答) |

### ③ 升级功能码「成对同号」的说法

| | 内容 |
|---|---|
| **原稿** | 升级家族请求与响应「用同一个数字」 |

| **修正位置** | [第 4.2 节](04-功能码总表.md#42-命名规律)、[第 12.1 节](12-固件升级.md#121-升级对象与功能码)、[附录 B.9](附录B-命令码表.md#b9-固件升级功能码组合) |

### ④ 组合帧第 1 段的字节范围

| | 内容 |
|---|---|
| **原稿** | 第 1 段范围为 `[0 .. 9+N]` |
| **实际** | 第 1 段（含自身 CRC）为 `[0 .. 7+N]`，共 `8+N` 字节；第 2 段从 `8+N` 开始，整条报文末尾才是 `AA 55` |

## E.3 源码中的疑似 bug

复核时在 App 源码中发现三处可疑实现，**已按「意图」而非「字面」写进本书**，此处单独列出便于读者自行验证：

### ① 通讯地址探测的比较值写成十进制字符串

```javascript
// utils/bleComApi.js
y = (255 & Number(g.data[0].data)).toString(16).toUpperCase().padStart(2, "0")
// ...
"161" !== y ? { action: "abort", reason: "antComAddressAbnormal" } : { action: "proceed" }
```

`y` 是十六进制字符串（如 `"A1"`），永远不会等于 `"161"`。
按注释「通讯地址探测正常(A1)」推断，应比对 `"A1"`。

**第四轮复核查清了这段代码的来历**：参数表里确有 **地址 706 = ANT 通信地址**，
默认值 `0xA1` —— 即十进制 **161**。作者本意应是「设备返回地址 == ANT 通信地址的默认值」，
写法上却一边十进制、一边十六进制。

**后果**：该分支可能恒判「地址异常」。若自己实现，直接比对 `0xA1`。

### ② AFE 结果码枚举的命名与文案错位

```javascript
// sdk/api/custom_analyze/bms_0x80_1.0.0.js
SUCCESS: { code: 0, desc: "成功" },
FAIL:    { code: 1, desc: "权限不足" },   // 命名 FAIL、文案却是"权限不足"
NO_PRI:  { code: 2, desc: "失败" },       // 命名 NO_PRI、文案却是"失败"
```

本书按 **desc 文案**给出（1 = 权限不足、2 = 失败）。若实测相反，以实测为准。

### ③ `andData` 描述符字段未被实际应用

从机数据的单体电压描述符里写了 `andData: 3`（屏蔽低 2 位标志），
但解析函数只调用 `getNumberVal(bytes, type, range)`，**没有使用 `andData`**。
详见 [E.2 ⑫ 从机数据的单体电压掩码](#e2-已修正的错误28-项)。

而 `unpack/小程序源包/` 里只提供了其中 3 个（新版）与 1 个（旧版）。

**影响范围**：

- ✅ **协议分析不受影响** —— BLE 协议的全部实现都在主包与 `pages_Detail` 里
  （`utils/`、`sdk/`、`pages_Detail/`），这些都完整；
- ⚠️ 上述 38 页的**界面与业务逻辑无法查阅**（本书对这些页面只引用 `app.json` 中的页面名，未涉及实现细节）；
- ⚠️ 旧版的 `donutAuthorize__` 授权页（第三方框架）同样缺失。

**补齐方法**：拿到完整的小程序包目录后重新解包即可：

```bash
cd unpack
./小程序解包工具/unveilr.exe wx -f -o 解包结果/wxe7b6244f6461fc6c     小程序源包/wxe7b6244f6461fc6c/151/*.wxapkg
```

（用 `*.wxapkg` 通配符把该目录下所有分包一起解，避免再次遗漏。）
