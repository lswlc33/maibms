# 多品牌生态适配：亚迪、明唐与广播识别

本轮按“识别品牌”和“协议已接入”分别登记。名称、服务 UUID 只是提示；新增直连协议须通过完整实时帧验证后才确认就绪。新增内容均为只读，不开放写参数、MOS 控制、校准或密码修改。

## 亚迪 F403

- Service：`6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
- Write：`6E400002-B5A3-F393-E0A9-E50E24DCCA9E`
- Notify：`6E400003-B5A3-F393-E0A9-E50E24DCCA9E`
- 请求传输为 ASCII 十六进制文本，解码后为 `F4 03 addrHi addrLo byteCount crcLo crcHi`；CRC16-Modbus 对前 5 个二进制字节计算。
- 应答同样是 ASCII 十六进制，解码后为 `F4 03 byteCount payload crcLo crcHi`。上游文档部分段落误称第三字节为地址；实际接收实现按字节数取长度，CRC 覆盖头、长度与 payload。
- 从 `0x1000` 读取完整 124 字节。使用 60/59/5 三个不同长度，减少无地址应答把上一块重复包当下一块的问题；每次仅一条在途请求。CRC 或超时失败整页作废并排空迟到数据，再重新读取。
- 仪表最小字段：LE u16 总压 @20 ×0.01V、SOC @48 ×0.1%、循环 @60、串数 byte63、单体 @68 起 LE u16 ×0.001V，最多 24 串。SOC=0 原样保留，不用容量比回填。
- 上游文字把总压写成 @22，但其原始样例 `F6 13` 位于 @20，实际解析也使用 @20；本轮依原始样例与实现一致处。容量互换、单位及电流定义等争议字段不显示为已确认量。
- 协议没有事务号或应答地址，无法从字节流绝对区分跨轮次、同长度的迟到旧应答。单在途、独特块长度、CRC 和失败后的排空只能减少误归属，不能宣称消除该线协议限制。

## 明唐 E1 TLV

- 只使用已知 `0000FA00-0000-1000-8000-00805F9B34FB` 服务，不回退通用电池服务 `180F`。
- 服务内按 writable / notify 或 indicate 属性生成有限候选，三端规则一致。优先用有响应写入（特征支持时）。订阅成功不算有电池数据。
- 唯一上行命令为 ASCII `stateread`。帧结构：`E1 11 00 xx lastIndexBE16 ...TLV... tail`，总长度 `lastIndex+1`，TLV 在 `[6,lastIndex)`，单项为 tagBE16、lenU8、value。
- 未发现可证实的 E1 校验算法；不得假装有 CRC。解析器检查固定头、长度、TLV 完整铺满、字段长度及合理值；需要总压、SOC 和其它有效实时字段才确认读数。
- 总压 tag10 按参考实现的 0.01V/count；单体 tag4 按 0.001V/count。参考头注释将总压写成 0.001V，与实现冲突，**尚待实物或厂商协议复核**，不是已经真机确认的单位。
- tag13/15 为充/放电流，大端 s32 ×0.001A，转成本项目“放电正、充电负”；tag27–31 为 s16 ×0.01℃；tag36/37 为 s32 ×0.001Ah；tag38 为 SOC。只映射结构和长度正确的已知项，不虚构 MOS、保护位义或循环含义。

## 验证与后续补齐

新增 Kotlin 用例和网页模拟 GATT 用例使用明确标注的合成帧；它们验证实现、分片、只读约束、刷新和失败路径，**不等于六品牌真机通过**。本轮没有上述保护板实物，Windows 也不能完成 iOS 原生构建或 CoreBluetooth 真机验证。

本轮执行结果：

- Kotlin 定向测试 29 项通过，覆盖两个新增解析器、品牌匹配、只读白名单和仓库层阻止未适配设备误连。
- Android `compileDebugKotlinAndroid` 通过；网页 `syncWebToDocs` 构建与同步通过。
- 网页最终产物 `verify-connect.mjs` 47 项通过，包含新增品牌及原有协议的连接、刷新、掉线与会话隔离用例。
- `compileCommonMainKotlinMetadata` 未完成：离线缓存缺少 Compose、serialization 等 metadata 依赖，失败在依赖解析阶段；不记作编译验证通过。
- 未做新增品牌真机 BLE、原生 iOS、模拟器界面或长期运行验证。

要补齐星恒/智霸/闪充和小哈完整直连，需要：实际广播名（含 Manufacturer Data）、GATT 服务与特征及属性、原厂 App 的握手/读取请求与对应通知、同一时刻原厂读数。若设备要求认证，还需确认合法用户凭据的本地使用方式；不靠猜测密码或修改保护板参数来试协议。
