## 1. 目标与背景

用 Kotlin Multiplatform + Compose Multiplatform 重写蚂蚁官方 BMS（电池保护板）管理 APP，替代微信小程序形态的官方客户端：

- **原生性能**：官方 APP 是 uni-app/Vue2 小程序编译产物（解包已证实），运行慢；本方案为原生编译。
- **完整深色模式**：Material 3 Expressive 主题，深色模式为一等公民。
- **双平台**：Android 为第一交付平台（用本机已安装的 MuMu 模拟器测试 APK，不另建 AVD），iOS 保留编译目标但不做真机测试（无设备）。
- **不依赖真机联调**：内置"虚拟 BMS"（Mock），在模拟器上跑通全部功能链路。

协议依据：本仓库 `docs/` 目录 20 篇协议逆向文档（帧格式、CRC、实时数据、参数表、控制命令、新旧固件差异等），内容来自官方小程序静态反编译，40 条内联报文经 CRC16-Modbus 独立复算，**尚未真机实测**。

## 4. 协议实现要点（来自 docs/，实现时严格对照）

1. **帧骨架**：`7E | 地址 | 功能码 | 寄存器(2B) | 长度 | 数据 | CRC(2B) | AA 55`；地址 `A1`=主机 / `C1`=并机第二台。
2. **短帧/长帧**：功能码 <0x10 固定 10 字节无数据区（长度字节=请求读取字节数，CRC 覆盖 [1..5]）；≥0x10 长帧（长度字节=数据长度，CRC 覆盖 [1..5+N]）。
3. **寄存器字节序不统一**：`01/02/03/04/06/07/22/23/26/51/52/53` 小端；`59`（AFE）、`70/80`（AFE 扩展）大端。照抄附录 D 样例，不要按规律推。
4. **CRC**：CRC16-Modbus（初值 0xFFFF，多项式 0xA001），不含帧头帧尾，线上低字节在前。
5. **组合帧**：一次通知可含两段帧，第二段省略 `7E 地址` 帧头，`AA 55` 只在末尾出现一次；两段 CRC 各自独立。
6. **解帧**：数据不足 break 等待；CRC 失败/结构非法丢 1 字节滑动重找帧头（15 §15.6 有 8 个自检场景，转单测）。
7. **实时数据 0x11**：头部 28B + 单体 2N + 温度 2M + 核心段 78B + 扩展段 24B(可选)；单体电压 `(u16 & 0x1FFF) ÷ 1000`（高 3 位是状态标志必须屏蔽）；温度 s16 有符号（-40 = 未接传感器）；扩展段判据 `总长 > 106+2N+2M`（不是 130+…，搞反永远读不到）。
8. **鉴权**：五级密码（一级默认 `12345678`，8 字节 ASCII）；运行权限 0=只读实时、≥1 可读参数、≥3 可写/控制；**权限不持久化**，断连/重启丢失，写操作前确保权限足够。
9. **写参数**：功能码 0x22 单寄存器（长度恒 02），值 = 工程量×倍率→u16→字节倒序；**写后必须发 51/07 保存**否则掉电丢失；结果码 2/3 时报文附带允许上下限，用于 UI 回显。
10. **轮询纪律**：BMS 不主动推送，500ms 轮询 0x01；发命令/读参数前**自动暂停轮询**、完成恢复；命令间隔 ≥200ms、一次只等一个应答。
11. **危险命令**：`51/11` 关系统、`51/12` 恢复出厂、`51/42` 恢复厂家、`51/28` 蓝牙关闭（失联需充电/按键唤醒）、清零类；操作前建议备份参数区 0~786。
12. **新旧固件差异**：新版是超集。按新版实现（245B 实时、&0x1FFF、扩展段按长度判断、`0xFAFx` 电池类型、三通道探测）；重启优先 `51/9`。
13. **BLE 链路**：服务 FFE0；通道候选 ffe1（主）/fff3-fff4/fff5-fff6，逐组探测；先订阅通知再发命令；MTU 新版请求 512（单写 = MTU−10，未协商按 20）；扫描过滤名称 `ANT` 前缀。

## 5. 关键设计决策（含 v1.0 反思修订）

### 5.1 BLE 与 Mock 同接口
`BmsConnection` / `BmsScanner` 接口定义在 `core/protocol`，真实/虚拟实现可切换（设置页"演示模式"开关）。没有真机也能端到端测试仪表盘、配置、控制全链路。

### 5.2 Mock 行为脚本（v1.0 反思 #8：Mock 必须能"测出东西"）
- 内置场景可切换：**正常充电 / 正常放电 / 静止 / 保护触发 / 告警 / 主动均衡**。
- 数据按正弦+噪声模拟：电流有正负变化、SOC 缓慢下降、偶发保护位翻转。
- 轮询节奏与真实设备一致（500ms 应答延迟）。
- 参数区：按附录 A 合成 786B 默认值；写 0x22 真实改变 Mock 状态，51/07 后"持久"（内存内）。
- 应答严格按附录 D 结构（0x11/0x12/0x42/0x61/组合帧模板）。

### 5.3 控制命令布局（v1.0 反思 #2：不要塞进仪表盘）
旧版控制页有 30+ 操作项。修订：仪表盘只放**最高频的充/放电开关、强制充电**（大按钮、状态直观）；完整控制项（电流归零、重启、清零类、恢复出厂、蜂鸣器、蓝牙开关、化学体系预设等）收进配置页顶部"控制与工具"分组。全部二次确认；高危项红色主题 + 输入确认。

### 5.4 参数编辑 UI（v1.0 反思 #3：用户视角而非工程师视角）
默认每项只显示**名称 / 当前值 / 单位 / 范围校验**；十六进制地址、倍率等收进条目展开详情（方便对照文档调试）。旧版按"电压/温度/电流/均衡/电池/其他/厂家参数"分页，本方案对应分组：电压保护、温度保护、电流保护、均衡、电池组与容量、SOC 表、系统参数。

### 5.5 权限流显式化（v1.0 反思 #5；v1.4 按设备分级密码模型重写）
- **密码模型（v1.4 落定）**：密码跟随设备——每台设备各自拥有 1~5 级共 5 组密码（协议 330/338/346/354/362 寄存器各 8 字节）+ 9 级厂家密码。"记住密码"按**设备**分类存储：`Map<设备标识, {密码, 等级}>`，而非全局单个密码。
- **默认等级自动升级**：为每台设备可选定一个"默认等级"（如 3 级）。连接该设备成功后自动用对应等级的记住密码静默校验（0x23），权限直接升到该级；未记住该级密码则回退到只读并提示。
- 连接握手后若权限 < 默认等级或需变更：仪表盘卡1 权限徽章/配置页横幅可发起校验。
- **存储决策（v1.3 落定）**：定义 `PasswordStore` 接口，v1 默认实现为 DataStore 明文（应用私有目录，设置项旁标注明文存储风险提示）；接口预留后续替换为 Android Keystore / iOS Keychain 加密实现。KMP DataStore 无内置加密，避免实现期在此纠结。

### 5.6 脏参数保护（v1.0 反思 #6）
ViewModel 跟踪"脏参数"集合；离开配置页或断连时有未保存改动 → 弹窗（保存 / 丢弃）。保存 = 对脏参数逐条 0x22 重发 + 51/07（协议无批量写）。

### 5.7 仪表盘布局适配（v1.0 反思 #7）
旧版主页是"固定头部 + 内滚动 + 双栏内滚动"多处嵌套滚动，Compose 照搬体验差。修订：整页**单 LazyColumn**；保护/告警双栏改为"各显示前 3 条 + 点击展开弹窗"（与 M3 交互一致）。

### 5.8 趋势图收敛（v1.0 反思 #9）
仪表盘内"最近 5 分钟"滑动窗口、每秒聚合 1 点，Canvas 简单绘制（电流/电压两条线）。不做专业图表库，不持久化（重启清空）。

### 5.9 Android 蓝牙权限（v1.0 反思 #7 补充）
API 31+ 扫描需 `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` 运行时权限；首次进入连接流程前申请；模拟器验证步骤中包含手动授权。API 26~30 设备另需 `ACCESS_FINE_LOCATION` 运行时权限才能扫描（Kable default-permissions 工件只补 Manifest 声明，运行时申请仍需自实现）。

### 5.10 扫码连接（v1.0 反思 #1）
旧版有"扫码连接"（扫电池二维码获取 MAC/配对码）。v1：Android 实现扫二维码填充设备；iOS 侧 expect 占位。广播数据解析按 docs/02 §2.1（`FFFF` 开头剥离、设备类型 0x056C、MAC 偏移、连接数高半字节）。

### 5.11 报文调试日志（v1.3 新增，开发者选项）
设置页提供开关：开启后记录全部收发帧的十六进制 + 时间戳 + 解析结果（环形缓冲，仅内存不落盘，支持复制/分享导出）。用途：接真机时对照 docs 逐帧核对，是"协议未经真机验证"风险（§9）的核心缓解手段；同时服务 Issue 反馈。

### 5.12 轮询与后台策略（v1.3 新增）
仅前台轮询（500ms）。APP 退到后台：暂停轮询，保留连接 30 秒后主动断开（省电、避免系统杀 BLE 回调）；回前台自动重连并重新校验权限（§5.5）。v1 不做前台服务/后台常驻监控，不做通知栏实时状态。

**密度原则（v2 修订，对齐官方 APP）**：仪表盘采用「**大卡 + 卡内自组布局**」，不做每格独立小卡——设备信息、状态列表、SOC 环、图标网格都是卡内分区，整页约 6 张卡；用 Row/Column 自组内部布局实现高信息密度（一屏可见电压/电流/功率/SOC/温度全貌），仅保护/告警和单体电压为独立双卡。

### 测试环境（MuMu 模拟器，不另建 AVD）

- 使用本机（Windows）已安装的网易 **MuMu 模拟器**进行 APK 测试；**不创建 AVD、不安装 Android Studio 模拟器镜像**。
- 连接：`adb connect 127.0.0.1:16384`（MuMu 12 默认端口；经典版 MuMu 为 7555；多开实例端口递增，连不上时在 MuMu「设置 → ADB 调试」中确认端口）。

- ABI：MuMu 12 为 x86_64 镜像（内置 ARM 转译），默认构建产物直接可装，无需专门出 ARM 包。

## 10. 真机验证清单（v1.3 新增，取得设备后按序执行）

前置：开启 §5.11 报文调试日志，全程录制帧日志留档。

1. **只读观察**（不输密码）：扫描/连接/通道探测、实时数据轮询、仪表盘数值与附录 D 期望值比对、保护/告警位域与设备面板表现比对、断连重连。
2. **读参数**：分块读全部参数区，与旧版 APP 同屏显示值逐项比对（重点：温度、容量 u32、SOC 表、电池类型 0xFAFx）。
3. **密码与权限**：一级密码校验、错误密码行为、断连后权限丢失与重新校验。
4. **写参数**（备用/低价值设备，先改一个值）：写 0x22 → 结果码 → 51/07 保存 → 断电重启 → 读回验证持久化；结果码 2/3 上下限回显。
5. **控制命令**：均衡开关、充/放电 MOS、强制充电、电流归零（无电流时）、重启系统；**跳过** 51/11 关系统、51/28 蓝牙关闭、恢复出厂/厂家、清零类（确有必要时单独评估）。
6. **新旧固件差异**：若同时有新旧两代设备，验证 245B/扩展段判据、0xFE 组合帧、通道探测三分支。
