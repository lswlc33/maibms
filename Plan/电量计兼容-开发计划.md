# 电量计（保护板中继器）兼容开发计划

> 版本：v1.2（2026-10-10）
> 状态：P1–P4、P6 已实施（蓝宝 + 陆行）；P7 真机校准待用户
> 依据：`unpack/解包结果/` 官方小程序（蓝宝 `wx58c0e70434915f95`、路行/陆行 `wx87cbe40059534375`）反编译结果 + 真机广播名确认。
> 变更：v1.1 → v1.2 **移除电领（`DL`）品牌**（其读数必须联网登录 + 正版校验，含防克隆自毁），只保留蓝宝、陆行。

---

## 1. 目标与背景

蓝宝 / 陆行两类**电量计**本质是"保护板中继器"：自己（BLE 或有线）连上保护板，把保护板的信号
放大/聚合后，再对手机输出。它们信号强，适合在**不需要高级设置**时作为优先连接入口。

目标：

1. 兼容两电量计的连接（按**蓝牙名称**判家族）；
2. 主页数据按"设备能力"渲染，避免出现看不了/误导性的空数据；
3. 检测到电量计时**隐藏配置页**（含密码相关），并**记住密码**；
4. 电量计与保护板**共用同一套仪表盘**，但整体逻辑、软件设置项、后端按家族**区分处理**。

连接选型原则（**用户行为 + 设置驱动**，不做自动择优）：
`用户指定的默认设备 → 上次连接设备 → 手动从扫描列表选`，优先级读设置。

## 2. 设备家族识别（按蓝牙名称）

| 广播名特征 | 家族 | 类型 |
|---|---|---|
| `ANT` 前缀 | 蚂蚁保护板 | Board |
| `BlueBabe` / `blue` / `lb` | 蓝宝电量计 | Meter |
| `EM2APP` 前缀 | 陆行电量计 | Meter |
| `CJ01` 前缀 | 陆行同厂控制器（非目标） | 忽略 |

匹配规则：广播名转大写后**最长前缀优先**（`BlueBabe` 先于 `lb`）。
已知风险：`lb` 与"凌博控制器"短前缀可能撞名——按最长/最具体优先缓解。

## 3. 连接策略（设置驱动）

- 扫描结果标注家族（保护板 / 电量计 + 品牌），列表可区分展示。
- 连接目标：`AppStore.autoConnectAddress`（用户指定）→ `AppStore.savedAddress`（上次）→ 手动选。
- 不做 RSSI 自动择优；"优先用电量计"由用户指定/记忆体现。
- 设备档案 `DeviceProfile` 增加 `family` 字段（老档案缺省 = Unknown，按保护板处理）。

## 4. 分层架构

| 层 | 改造 |
|---|---|
| `transport/DeviceFamily.kt` | 家族枚举 + 名称匹配 + 类型（Board/Meter） |
| `transport/BmsTransport.kt` | `ScanDevice` 加 `family`；`setTargetFamily()` 默认方法、`currentFamily` 流；`BleChannel` 增 `Meter`（FFE2/FFE1） |
| `AndroidBleTransport` / `IosBleTransport` | 扫描按家族过滤；连接前记录家族；电量计走 `Meter` 通道并跳过 ANT 探测 |
| `data/BmsRepository` | 解析并透传家族；按家族选协议/轮询；暴露 `currentFamily` |
| `data/DeviceProfiles` | 档案加 `family` |
| `protocol/meter/` | `MeterProtocol` + 两实现（蓝宝 FA50 / 陆行 Modbus） |
| UI | 按 `kind` 隐藏配置页；按 `caps` 显隐卡片 |

## 5. 两家协议适配要点

- **蓝宝**：`FA 50` 帧（`dst 0x28`→`src 0xA0`），`0x15` 读表1/表2，私有 CRC，匹配码默认 `06×6`；
  表1 给总压/总流/SOC/温度/剩余容量/功率/最高·最低单串/压差/绑定保护板名称·MAC·类型，表2 给
  设备序列号/版本/电池类型/串数/容量/循环次数。
- **陆行（EM2APP/EM02）**：模块是 BLE 上的 **Modbus RTU 从站**（地址 1，功能码 03）。
  ⚠️ 它用的是 `pages/mianEM02/EM02/EM02.js` **自己的协议**，**不是** `utils/bluetoothService.js`
  （后者 0/52/81/130/190 是 CJ01/ECU02 等老产品的表——用错会一路收到 `01 83 02` 非法数据地址）。
  正确命令（每拍 4 条）：`4000/89`→len 178 设备信息、`4092/54`→len 108 实时（单体/温度/电压/电流/功率/容量/SOC）、
  `4200/45`→len 90 BMS 数据（绑定/连接状态 + 中继品牌/名称/MAC）、`4152/48`→len 96 循环/串口。

统一映射到 `BmsStatus`，量纲在 `MeterReading` 落地（蓝宝 `/100`、`/1000`；陆行 `/10`、`/100`）。

## 6. 主页数据处理（能力位驱动）

`BmsStatus` 挂 `caps`，卡片按能力显隐——**有能力才显示真实值，没能力整块隐藏**。

| 首页元素 | 蓝宝 | 陆行 | 策略 |
|---|---|---|---|
| 保护/告警双卡 | ✗ | ✗ | 隐藏（无位域） |
| 充/放 MOS、均衡 | ✗ | ✗ | 不显示该行 |
| 逐串单体 | ✗（仅最高/最低/压差） | ✗ | 降级为"最高/最低/平均/压差"汇总 |
| 多路温度 | △1 路 | △最多 5 路 | 有几路显示几路 |
| 扩展时间(充/放剩余/本次充电时长/上次间隔/运行时间) | ✗ | ✗ | 隐藏 |
| 权限等级 chip | ✗ | ✗ | 电量计模式隐藏 |
| 控制行 | ✗ | ✗ | 隐藏 |

## 7. 电量计模式（整体降级）

- `kind=Meter`：隐藏"配置" tab（参数读写/控制工具/固件升级），深链重定向到仪表盘；
  设置页保留设备/快照/通道/关于。
- 密码：按设备存 `level 0`（蓝宝=6 位匹配码，陆行=无）；连接时自动带上并记住。

## 8. 逻辑 / 设置 / 后端分叉

- 逻辑：`BmsRepository` 按 family 选协议 + 轮询 + 能力；共用 `BmsStatus`/仪表盘。
- 设置：连接目标、密码、能力项按 `kind/family` 分别存/展示。
- 后端：两家电量计**纯离线**（无云端依赖）；快照/配置缓存按 family 分存。

## 9. 分期

1. **P0**：确认广播名（✅ ANT / BlueBabe / EM2APP）。
2. **P1**（✅）：`DeviceFamily` + 名称匹配 + 家族透传（扫描/连接）+ 档案记 family + 单测。
3. **P2**（✅）：蓝宝协议（FA50）组帧 + 表1/表2 解码。
4. **P3**（✅）：陆行协议（Modbus RTU）组帧 + 三块应答解码。
5. **P4**（✅）：能力位 `DeviceCapabilities` + 首页卡片按能力显隐。
6. **P6**（✅）：电量计 UI 分叉（隐藏"配置"标签）+ 密码记忆（level 0，按设备存）。
7. **P7**（部分）：编译/单测全绿、ANT 直连零回归；**真机校准待用户**（量纲/字节序需抓包核对）。

> **P5（电领）已按需求移除**：其读数必须联网向 `hiiyun.com` 取 ECDH 密钥（`0x00` 握手）+ 设备 UID
> 正版/绑定校验（不通过会给设备下"自毁倒计时"），属外部服务 + 合规敏感项，不实现。

## 10. 已实施明细

- **家族判定**：[DeviceFamily.kt](../composeApp/src/commonMain/kotlin/io/github/lswlc33/maibms/transport/DeviceFamily.kt)
  （`Ant / LanBao / LuXing / Unknown`，名称匹配最长前缀优先，`isTarget` 排除 `CJ01`）。
- **能力位**：[DeviceCapabilities.kt](../composeApp/src/commonMain/kotlin/io/github/lswlc33/maibms/data/DeviceCapabilities.kt)
  （Board/LanBao/LuXing 三套），挂到 `MockBms.caps`。
- **电量计协议层**：[protocol/meter/](../composeApp/src/commonMain/kotlin/io/github/lswlc33/maibms/protocol/meter/)
  `MeterProtocol` 接口 + `MeterReading` + `forFamily`；蓝宝 `LanBaoProtocol`、陆行 `LuXingProtocol`。
- **数据通路**：`BmsRepository` 按家族选协议；电量计模式轮询写帧、通知解码 → `MockBms.applyMeterReading`；
  跳过蚂蚁的"升权 + 参数区读回"连后序列。
- **首页显隐**：`ProtectAlarmCards` / `StatusCapacityCard`(MOS·均衡行) / `MetricGridCard`(扩展时间行) /
  `BatteryCard`(权限 chip) / `CellGridCard`(逐串→最高最低压差汇总) / 控制行 全部按 caps 处理。
- **电量计模式**：`App.kt` 隐藏"配置"标签并重定向深链；`BmsRepository.setMeterSecret` 记住设备密码（level 0）。
- **扫描 UI**：扫描列表显示家族标签（`… · 蓝宝电量计`）。
- **中继信息卡**：电量计模式下仪表盘显示「中继的保护板 品牌 / MAC」——蓝宝可报品牌 + MAC
  （`communicationMethod` + `boundDeviceMac`），陆行报品牌（`batteryType` 码表）。
- **测试**：[DeviceFamilyTest.kt](../composeApp/src/desktopTest/kotlin/io/github/lswlc33/maibms/transport/DeviceFamilyTest.kt)、
  [MeterProtocolTest.kt](../composeApp/src/desktopTest/kotlin/io/github/lswlc33/maibms/protocol/meter/MeterProtocolTest.kt)；
  `desktopTest`（全量，含既有回归）与 `compileDebugKotlinAndroid` 均通过。

## 11. 已知不确定（需真机校准）

- 陆行：已改为 EM02.js 的真实协议（4 条命令 4000/4092/4200/4152，响应 178/108/90/96），量纲按官方换算
  （电压 `/1000`、电流 `/100`、容量 `/10`、单体 `/1000`，小端）；4 条命令 CRC 已逐条核对。待真机确认字段是否合理。
- 蓝宝：多字节按**大端**解析已由 `utils/comm.js hexToDecimalism`（`BigInt("0x"+hex)`，不反转）确认；
  `decimalPlaces` 取自反编译常量；匹配码默认 `06×6`，已支持 12 位十六进制（如固定码 `1821A33B4556`）。
  应答已加 **CRC 校验**（`crc.js crcCheck`），并按数据区长度（111/134）分派表1/表2，回显数据号作兜底。
